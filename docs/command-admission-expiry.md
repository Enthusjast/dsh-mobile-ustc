# 命令准入的 grant 实时期限

六类命令共用同一授权后的登记事务：`message.submit`、`session.cancel`、`session.archive`、
`session.model.select`、`question.answer` 和 `session.create`。timed question 的持久答复也
归入 `question.answer`；附件消息在同一事务中登记命令及文件引用。

原有账号、设备密钥、成员关系、安装、runtime、grant 版本/范围和会话或工作区检查继续执行。
这些检查取得当前资源行的共享锁后，准入入口使用 PostgreSQL `clock_timestamp()` 重新核对
该 grant 的期限。锁查询的筛选表达式可能在等待前已求值，持有行锁也不能阻止时间流逝。

新命令和相同 ID/摘要的重试都可能继续等待命令行、审计或附件准入。完成这些步骤后，事务
在提交前再次核对期限；这是本次准入的最终决策点，数据库提交和网络应答可能随后完成。
过期返回既有 `access.denied`，不向 Host 返回可转发的成功准入结果。

新尝试因过期失败时，命令 `received`、成功准入审计、附件引用及本次 `file.message_bound`
审计整体回滚。已存在命令的重试则保留原始事实，不增加成功证据或新文件能力。数据库故障
使用原有服务不可用错误，不将故障当成到期，也没有新增自动重发或重新执行策略。

手机 ticket 的三十秒期限只约束初次接入；已建立 WSS 连接使用独立连接租约。命令复核
当前 grant 期限，不将已经消费的 ticket deadline 当作后续业务的期限。连接关闭、授权
撤销、scope 和 key version 等原检查仍各自适用。

## 结果与查询边界

这项检查约束新的手机命令准入，不删除历史，也不拒绝当前 Host 报告已存在命令的执行事实。
Host 结果仍须匹配当前安装密钥、runtime/epoch/connection、原设备/request/target/digest
并遵守状态转换；它们可以在手机 grant 到期后继续持久对账，不因此恢复手机权限或工具许可。
历史查询继续要求当前读取权限，不能把一条旧状态当成新的执行授权。

## 证据

修复前的隔离 PostgreSQL 回归复现 19 个过期后仍成功的场景：六类命令分别等待资源行、
已有命令行和审计锁，以及附件消息在完成文件绑定后的 readiness 重查等待。测试观察真实
数据库锁，使用数据库时钟等待短测试 grant 到期，不修改系统时间或生产 TTL。
修复后操作被拒绝，并核对新命令、成功审计和文件引用回滚；原命令保留。正向用例确保
已消费 ticket 的旧 deadline 不会替代 socket 租约，且当前 Host 可继续报告已有命令终态。

完整 Go race / PostgreSQL 和正常本机 npm DSH `0.2.1-rc.2` 双节点链路分别验证。
身份、模型和短期限均为本地夹具，本轮不进行 Android APP、真机、大负载或厂商推送验收。
新增时间查询的目标负载成本仍需独立测量。本次没有协议、数据格式或数据库迁移。

共享主体限流仍是单独的待办：现有主要是每连接操作窗口，不能据此宣称多个连接或节点已
共享用户、设备、安装和会话的速率预算；本次期限复核不改变这一边界。
