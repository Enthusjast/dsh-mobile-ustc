# 上传、导出与下载准入的期限边界

文件上传和导出登记、首次扫描提交、上传能力签发及下载 opened 许可，在全部资源检查和
账本/审计等待结束后按当前时间重新核对期限。资源锁固定身份、设备、作用域和 grant
版本，截止时间仍会继续流逝。

## 数据库决策点

新上传/导出登记在配额、文件、对象键和审计写入后，读取数据库实际保存的期限并复核
当前 grant、文件及保留期；导出还检查原 Host 凭据与来源窗口。新增登记失败时，配额
预留、文件、来源、对象键和两类审计整体回滚，不返回已接受记录。

首次提交扫描在状态、上传证明及审计写入后再次检查。Host 导出确认会把文件窗口延长到
后续扫描/保留阶段，因此最终检查仍保留原上传/来源/文件窗口，不能用本次延长后的期限
掩盖等待期间的到期。所有明确的单行登记、配额扣增、来源证明和审计都要求实际写入；
被忽略的写入不能留下部分成功事实。

手机 PUT 地址与文件提交采用不同期限：原 PUT 窗口结束后，已经存在的隔离对象仍可在
当前 grant、文件及保留期内提交扫描。此路径不会签发新的上传地址。已提交的上传/导出
扫描重试只返回原事实，不重复启动扫描或恢复来源许可；仍保留既有当前设备、版本、
角色、范围及 Host 校验。

下载授权在资源/来源读取完成后重查 grant，租约受文件、保留期和 grant 的较早期限限制。
opened 审计在提交前重新检查这些权限及原许可期限；到期时回滚本次 opened，组件在
审计返回后还会核对许可与生命周期，避免过期后才打开对象存储。已发生下载的 served /
cancelled / failed 结果仍能在原权限结束后保存，不能把结果审计当成新的 opened 许可。

数据库检查是本次准入的决策点；COMMIT、响应和后续网络 I/O 可能稍后发生，不以应答到达
时间定义授权生效。流式读取继续执行原有五秒租约、周期复核、token/文件期限和取消检查。

## 预签名能力

手机上传和 Host 导出都按上传、文件、保留期中最早截止时间计算签名 TTL，并保留原有
十五分钟/五分钟上限。预签名返回后再次检查其真实 ExpiresAt：已经过期或晚于有效窗口
的 URL 不返回给调用者，不通过改写响应日期来伪装缩短实际 S3 签名权限。

已完成的登记继续保留供原 request ID 对账；签名失败不会另建意图，也不宣称撤销已经
签发的 PUT。隔离上传本身仍不授予扫描发布、Host 交接、原生 receipt 或消息执行权限。

## 验证

隔离 PostgreSQL 先复现 27 个越期成功场景，覆盖新登记、首提交、第二类来源审计、来源
读取锁及下载 opened 审计。修复后逐项确认真实等待，按数据库墙钟到期后释放锁，并对比
文件/来源/对象/扫描/审计及三类配额，确认全量回滚。20 个写入忽略场景验证失败关闭和
恢复后的重试；正向测试保留 PUT 到期后的合法提交、来源到期后的历史确认和撤权后的
已发生下载审计。

组件测试覆盖过期、延迟、越过上传/文件/保留窗口的预签名结果，以及有效短能力；下载
审计跨过许可期限后确认对象存储打开次数为零。完整 Go race/隔离 PostgreSQL 和本机
npm DSH `0.2.1-rc.2` 双节点正常链路分别回归。对象、扫描、身份和模型为本地协议夹具；
未修改 Android APP，未运行大负载、真机或厂商配置，也不声明真实生产存储/病毒引擎已验收。
