# Android command delivery and encrypted outbox

The foreground session client now sends text in `queue` or `steer` mode and can request cancellation of the current runtime epoch. Reading, heartbeat and command frames share one authenticated TLS WebSocket. Commands require their explicit current grant actions and negotiated capabilities; write support is unavailable to a read-only directory grant. Status reconciliation additionally requires `command.status`. A saved offline intent remains local until the user explicitly sends it.

`:core:command` owns immutable request/runtime/session/type/payload identities, the exact Go/TypeScript JCS digests and delivery knowledge. The [workspace-targeted creation flow](android-session-creation.md) shares the same coordinator and request namespace, with a separate settled result UUID. Text preserves whitespace and scalar Unicode while respecting the native 32,768-code-point bound, allowed controls and the 64 KiB complete wire frame limit. Cancellation includes the original epoch in its digest; neither a retained dialog nor an old local intent can silently target a restarted runtime. A command ID never receives a different body or target.

`:core:data` stores the complete command journal in Room 2.8.5 with SQLCipher Android 4.19.1 and AndroidX SQLite 2.7.1. Room uses KSP 2.3.12; the existing application Hilt processor remains KAPT. Exact dependency locks and downloaded-artifact SHA-256 verification metadata are maintained. The database and its WAL are encrypted, under `noBackupFilesDir`; the app continues to exclude backup/data extraction and enable secure live windows. Schema version 2 also stores the [confirmed transcript cache](android-transcript-cache.md), with an explicit migration preserving original command identities and attempt state.

Each account/organization/deployment/internal-user/device combination has a distinct database and random 32-byte database password. A purpose-separated, non-exportable AndroidKeyStore AES-256-GCM wrapping key authenticates the full owner metadata. It is separate from token storage, DPoP and approval keys. Secure/unlocked device gates apply; the API 31–34 unlocked-key workaround follows the existing account vault. A missing/corrupt wrapped key or mismatched owner never creates a replacement database or falls back to plaintext. Explicit account cleanup destroys decryptability before removing its local data; runtime revocation removes the affected rows.

The journal transaction commits the original body and request ID before dispatch is eligible. A second durable transaction changes pending to reconciliation-required and increments attempts before a socket write. SQLCipher uses WAL and `synchronous=FULL`; failures leave the original intent and cannot produce a falsely successful acknowledgement. Closing or changing account/navigation generations fences old work. On reopen, an attempted command stays uncertain; reconnection never automatically emits its body again.

Local delivery knowledge and remote persistence facts are separate. Relay `received` is not host durability. `host_accepted` means the host journal saved the body. `agent_queued` means native admission and its persistence barrier were acknowledged; it does not claim the task or a model reply finished. `outcome_unknown` retains uncertainty and previously proved milestones. Reordered nanosecond timestamps cannot regress accepted facts, and conflicting targets/digests/terminal results are rejected.

Device-facing wire receipts omit an origin identifier. The current Go server already isolates receipts by device and ticket resource scope. The SDK uses these frames as refresh hints and obtains durable facts through the current device's DPoP-protected command-status request, including its verified device selector. It does not turn an unsolicited wire ID into a local command or apply a stronger hint over weaker authoritative status. Failure to query a missing/inaccessible status is uncertainty, not proof that nothing ran.

Manual retry keeps the original ID/body. It re-queries the device's status and is eligible only while it still reports `received` with no previously proved host save. Host acceptance, native admission, rejection, settlement and unknown outcomes are not replayed. The host's existing durable deduplication/recovery rules remain authoritative. The UI offers status reconciliation for uncertain results and does not invent a new request ID when a reply is missing.

The outbox holds at most 128 retained records and 8 MiB of encoded intents per owner. Capacity pressure may evict older delivery-confirmed records; unconfirmed/unknown rows are retained and stop further creation at the bound. Session/runtime/account scoping applies to all reads and updates. Pending/uncertain cards are separate from the native transcript; there is no text-matching attribution of a prompt to an assistant reply. An admitted command's body is hidden from its status card instead of becoming a duplicate optimistic transcript event.

The composer supports explicit queue/steer selection, local save while offline and manual transfer of a saved request. Unsubmitted text uses ordinary memory rather than saved instance state. The interruption dialog is tied to the observed epoch and explains that native pending inbox work is not cleared. Grant changes, authentication loss and logout close the session before sensitive cleanup. The standard APK still requires verified public school deployment configuration; no issuer/model fallback or desktop credential is embedded.

On 2026-10-25, all 124 shared JVM tests passed without failures or skips, and Android check/lint plus debug app/test APK builds passed. The complete API 26 application suite passed 72 tests, including SQLCipher/platform/controller/Compose command cases and the new structured-question flows. The current suite also covers encrypted transcript recovery. The nine native session/chat cases passed again after periodic exact-session authority checks and offline control delivery were added; the independent encrypted schema migration test passed as well. Verification is split between those suites and real Kotlin/Go/PostgreSQL/npm DSH composition. The SDK composition checks actual text admission, durable status, native message observation, refusal to replay an admitted ID and actual cancellation of a held native model turn. ELF load segments and APK placement of all four shipped SQLCipher ABIs were checked at 16 KiB alignment. These checks do not replace physical 16 KiB-device, real school identity, OS kill/power-loss, production key-provider, offline-policy or complete M2 acceptance.

The [question-answer coordinator](android-questions.md) uses the same persisted request namespace, with local definition context excluded from wire digests. Before any initial or repeated answer write it rechecks the current routed question, expiry and full structured answer. Foreground consumption and timed late-message admission remain separate facts; neither implies task completion.
