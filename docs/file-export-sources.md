# 受限导出的 Host 来源层

本阶段实现真实 npm DSH `0.2.1-rc.2` 的导出来源解析、受限文件读取和运行时条目。它已接入 `ProbeRuntime` 的清理生命周期，尚未在 Relay 宣告导出能力；服务端导出账本、扫描 / 对象中转、鉴权下载和 Android 保存入口仍需接入。现有文件上传 / 消息链路见 [Android 文件](android-files.md)。

## 两类来源

`registerSessionAttachment` 只接受当前移动会话的原生日志位置和 content 下标。Host 重新解析当前 runtime 的根会话与工作区，通过真实 Session Controller 取得已保存的精确事件，再从该事件读取文件或图片引用。显式用户输入、已回答的迟到问题、assistant 和 tool 消息中的附件可成为来源；模型注入的 user-role 上下文继续拒绝。

持久检查点失败、位置尚未保存、引用缺失、子会话接管或另一个 profile 的移动 ID 都会拒绝。文件以原生日志中的内容摘要、显示名和准确长度校验；图片导出实际保存的归一化字节，不声称还原原始上传编码。冷会话的读取不激活 Agent。调用方不能提供原生 attachmentId、receipt、绝对路径或任意 JSON 引用作为附件权限。

`registerWorkspaceArtifact` 供可信 Host 交付物选择器登记文件。配置在对应工作区声明允许的目录，目录与实际文件选择均留在 Host：

```yaml
workspaces:
  - id: project
    cwd: /absolute/path/to/workspace
    exportRoots:
      - id: reports
        directory: deliverables/reports
```

目录必须是合法的相对路径；拒绝绝对路径、`..`、空组件、控制字符、非标量 Unicode 和两种路径分隔符混入组件。每个工作区最多八个唯一目录声明，最多十六级。`.` 表示 Host 明确允许整个工作区；省略 exportRoots 时不提供工作区文件来源。目录标识不直接变成手机路径选择器，手机后续只能选择 Host 已登记的不透明条目。

工作区来源只在当前锁定的 `LocalFileSystem` 或 `SandboxedFileSystem` 中启用：两者原生读取语义相同，沙箱的变更策略继续由原服务执行。未知文件系统、不同执行世界或读取策略包装器需要各自的安全适配，不能因为 Host 上恰好存在同名路径而直接读取。服务被替换或目录策略撤销后，旧来源拒绝继续。

## 文件版本和字节

当前适配器使用 Linux procfs 的内核 fd 相对解析，从文件系统根开始逐组件以 `O_NOFOLLOW` 打开目录和文件；目录要求 `O_DIRECTORY`，文件使用只读与非阻塞标志，避免先跟随链接或卡在 FIFO 上。最终对象必须是普通文件。工作区文件拒绝多个硬链接；原生不可变附件的别名可使用硬链接，但必须匹配来自原生日志的完整 manifest。

打开后固定同一文件描述符，记录设备、inode、长度、mode、mtime、ctime 和链接数。每次读取前后重查版本；目录路径被替换为链接时仍只读取已固定的原对象。原文件发生变化则拒绝，不转向新路径。

来源先流式计算完整 SHA-256，再产生可展示的 manifest。后续读取使用同一描述符，再计算长度和摘要，并在最终验证完成前保留最后一块。所有块最多 64 KiB，不收集整个文件；调用方提前停止、取消、租约检查失败或版本变化都会关闭来源。原生附件还须匹配原生日志中的摘要。单文件来源上限为 2,000,000,000 字节；这项边界检查不代表已完成 2 GB 的对象服务或 APK 性能验收。

当前适配只支持 Linux + procfs。macOS / Windows 需要能够提供相同保证的实现，当前不会回退为 realpath 后直接 open，也不会宣称这些平台已经通过导出验收。

## 条目、授权与清理

`FileExportRegistry` 产生随机 export_id，公开值只有 ID、origin、名称、长度、摘要和到期时间。它不持久化主机路径、原生存储标识、文件正文或文件描述符。每个条目绑定当前 runtime、明确会话及原用户 / 设备，不可跨会话或转给另一部手机。

来源层要求调用方传入已验证连接的生命周期 signal 和同步 `current()` 授权租约检查；它不会把 UUID 当成身份认证。后续 Relay 适配仍必须验证独立的 file.download 权限、当前 grant / device / epoch 和资源归属。每块读取继续检查原授权；新读取者也必须具有同一用户 / 设备身份与当前权限。

同时最多准备两个摘要、保存三十二个来源。条目最多存活五分钟，使用墙钟和单调时钟检查；回退或过期不能恢复权限。读取只消费一次，失败或提前结束也不复用该文件句柄。撤权、断开、显式释放及运行时关闭使条目失效并关闭描述符。插件卸载等待已登记和准备中的来源清理；重建产生新的来源空间，旧 ID 不可使用，仍在原生日志中的附件可重新核对后登记。

这些内存条目是对象中转前的来源资格，不是已经扫描通过的下载对象。后续导出仍要使用服务端配额、扫描、保留期限、审计和撤权下载链路，不能直接把来源流暴露为无鉴权 HTTP 响应。

## 验证

2026-10-26 的 `npm run verify` 已通过契约检查、严格类型检查、构建和 230 项 Host 测试。新增十六项用例覆盖：

- 二进制 / 空文件、64 KiB 块、2 GB 超限拒绝、摘要副本不可修改内部结果。
- 最终 / 父级 / 根目录链接、特殊类型、工作区硬链接、目录替换和读取中改写。
- 撤权、取消、提前停止、关闭时准备中的任务、描述符释放与并发 / 数量限额。
- 真实 DSH 持久文件和图片、设备 / 会话 / profile 隔离、隐藏上下文拒绝、冷会话恢复且不激活 Agent。
- 原生只读沙箱继续拒绝写入，未知执行世界拒绝读取 Host 同名路径。

本机记录为 `.local/file-export-world-tests-second.log`、`.local/file-export-host-verify-final.log`。这是 Host 来源层证据，不替代尚未实现的导出协议、服务端下载、Android 保存或跨平台验收。
