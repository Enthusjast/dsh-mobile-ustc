# Android foreground session reader

The Android application now opens the authorized runtime's session directory and reads a selected session through the existing TLS Relay. The shared reader owns subscriptions, bounded logical reassembly, snapshots, native events, assistant attempts, history, heartbeat and fresh-ticket reconnection. The foreground UI shows connection, persistence, paging and offline states and supports collapsible reasoning. This delivery is read-only; sending, cancellation, questions, signed approvals, binding UI and an encrypted message database remain work. M1/M2 have not passed their complete exit gates. School identity configuration is unavailable; development continues with local fixtures as requested.

`RemoteApi.readTicket` posts the explicit runtime and `session.read` scope through the existing DPoP resource client. The request uses a fresh proof, access-token hash and resource nonce. One middleware `use_dpop_nonce` challenge can retry before admission with a new proof JTI; ordinary write/network failures are not replayed. The response must match the requested runtime and exact literal scope, have a valid grant version and contain a fresh canonical 256-bit token. A ticket object is single-use even after failed upgrade. Its raw value stays out of URLs, UI state, persistence and error text.

Scope selection follows the authenticated directory: prefer a session explicitly present in the grant, otherwise its returned workspace must be present in the workspace grant. `session.list` does not imply body read. The client does not manufacture a workspace or convert a workspace grant into a literal session grant. Service ticket issuance and each read still recheck current authority independently.

The fixed endpoint is the configured HTTPS origin's `/v1/realtime`, using `Authorization: DSH-Ticket` and `Sec-WebSocket-Protocol: dsh.remote.v1`. TLS uses the standard platform provider, the HTTP client's trust/hostname/pin policy and its TLS 1.2/1.3 cipher policy. The current connector opens a direct socket and rejects a selected HTTP/SOCKS proxy before connecting instead of bypassing it; proxy tunneling, HTTP/2 extended CONNECT, certificate-rotation deployment and target-network acceptance remain gates. Redirects, cookies and negotiated WebSocket extensions/compression are not used.

The narrow RFC 6455 text adapter checks the HTTP upgrade/accept key and subprotocol with a 16 KiB header budget. Server frame lengths are checked before payload allocation; both an individual frame and a complete text message are limited to 64 KiB. Server masking, reserved bits/opcodes, nonminimal lengths, invalid control/close frames and malformed UTF-8/JSON are rejected. Up to 64 RFC fragments may compose a message within five seconds; UTF-8 is decoded only after complete byte reassembly so a scalar may cross fragment boundaries. Input is limited to 200 frames/second. Reads apply TCP backpressure; the reader has a two-frame incoming channel and up to eight bounded serialized writes, each with a five-second deadline. Cancellation closes the underlying TCP/TLS socket to interrupt blocking I/O. Protocol framing and broader hostile-peer/network behavior still require production security/load review.

Application `session.fragment` groups are separate from RFC fragmentation. They retain one subscription/request/sync/content identity, accept 2–52 ordered canonical-base64 pieces of at most 40 KiB and publish only after complete UTF-8/JSON validation. Each logical payload is limited to 2 MiB, depth 32, 65,536 values and a ten-second reassembly deadline. The display parser does not change the existing 128 KiB signing/configuration parser. Retained history is limited to 4,096 native records and an 8 MiB conservative content-accounting budget; stream blocks/chunks/text also have explicit bounds. Reaching the history limit stops further paging; a snapshot that cannot fit triggers a smaller opening window or an explicit error.

`SessionWindow` preserves the opening cursor for all pages while native live events advance a separate observed cursor. Dense native positions and global assistant revisions/indices are checked; changed repeats and gaps require a replacement snapshot. Compact assistant baselines restore the stream before suffixes are applied. A known attempt's durable assistant event stays hidden until the matching committed end names its event type and native position. Abandonment discards the transient. Model-only surface replacements do not erase or duplicate the human transcript. Persistence checkpoints may lead observation and never move backward; a failed checkpoint remains visible as a warning.

Each physical reconnect obtains a fresh ticket, socket, subscription and replacement snapshot, with bounded jittered backoff. Explicit offline/terminal states require a user retry. Ping/pong runs every 20 seconds. Pagination deadlines do not cancel socket reads, and only one correlated page is in flight. Logical fragment and held-settlement deadlines require resynchronization. A temporary memory-only cache contains confirmed durable display rows, excludes live attempts and held settlements, and expires with the previous connection lease using wall and monotonic time. It is cleared on epoch change, revocation, credential loss, backgrounding, account disposal or logout. It is not an encrypted persistent message cache or process-kill recovery.

The controller fences directory jobs and reader collectors by account and navigation generation. Leaving the foreground closes the reader; returning rechecks the session directory before opening a fresh connection. A narrower directory grant retires the old view. Resource-specific read revocation clears the body and reconciles current authority while retaining an otherwise authorized account. Directory-only access never enables reading, and absent/malformed access metadata fails closed. The UI distinguishes no messages from unavailable offline history and labels temporarily cached records separately.

The device hello advertises only `connection.heartbeat.v1` and `session.read.v1`. Its digest uses the same normalized, length-prefixed encoding as Go/TypeScript. `contracts/security/relay-device-hello.json` is a public-only shared vector consumed by all three languages. The ES256 `dsh-relay-handshake-proof+jwt` binds device issuer, fixed realtime audience, current challenge/connection/nonce, runtime, normalized hello digest, issue time and a fresh proof JTI. It contains no caller-supplied JWK or desktop credential. The proof signer independently verifies its provider's signature against the loaded public key.

`hello.ok` must preserve connection/device/runtime identity, grant version and ticket scope, select only requested capabilities, and keep protocol/frame/heartbeat settings within v1. Server time and the five-minute lease are bounded; resource use is further constrained by the original access-token deadline and monotonic elapsed time. Receiving checks lease validity before and after delivery. The reader reports READY only after applying its correlated subscription snapshot.

On 2026-10-25, JVM protocol/network tests and full Gradle lint/APK checks passed. Tests exercise the shared digest, exact scope/role/identity/capability/lease denial, canonical nonce and RFC 3339 precision, real HTTPS ticket issuance with one nonce challenge, TLS upgrade and key verification, credential reuse denial, redirect/subprotocol substitution, fragmented Unicode with interleaved ping/pong, header controls, 64 KiB boundaries, overlarge advertised lengths before payload reads, binary/masked/truncated/invalid frames, continuation floods, close UTF-8 and cancellation. A deterministic 4,096-header corpus also checks bounded parsing and rejection behavior. These tests are targeted evidence, not a general-purpose WebSocket or production-security certification.

The shared suite now contains 66 JVM tests without skips. It includes adversarial display JSON and application fragments, compact streams, duplicate/gap and settlement behavior, fixed history cuts, exact directory scopes and real TLS reader tests for concurrent history/live events, page timeout/retry, fresh credentials/subscriptions, replacement snapshots, heartbeat, cancellation and revocation. Dense live positions are also tested across idle/page deadlines. Frame delivery and logical timers use atomic channel selection so a timeout cannot discard an already received element; transport EOF is propagated after queued control frames, including revocation, have been consumed. Android lint and debug app/test-APK assembly passed with `./gradlew --max-workers=1 check :app:assembleDebug :app:assembleDebugAndroidTest`. No lint checks were disabled.
