# Signed approval authorization leases

The Go control-plane store can now produce short signed authorization proofs from an already accepted decision. TypeScript independently verifies the authority and phone signatures, then keeps ephemeral evidence for the synchronous native final guard. This implements an internal provider and host verifier/cache; the [optional server HTTPS/WSS transport](approval-protocol.md) now connects the server operations. Normal plugin callback ownership, real IdP configuration, host key provisioning and Android signing remain separate work. The configured Relay advertises the capability; the normal plugin does not yet offer it.

The lease payload uses domain `dsh-mobile-ustc/approval-authorization/v1`, audience `dsh-approval-host/v1`, protocol 1, and an HTTPS issuer fixed by deployment. It binds host/installation/runtime/epoch/session/approval/execution UUIDs, the exact host connection ID, a fresh lease UUID, owner `approval.decide`, context and canonical decision digests, policy, user/device/key/grant versions, registered approval-key thumbprint and public key, assurance profile, original authentication time and issue/expiry times. Public JWKs have exactly `kty`, `crv`, `x` and `y`. Full arguments, native call IDs, resource facts and nonce are absent from the lease.

Compact JWS is ES256, protected header exactly `{alg,kid,typ}`, with type `dsh-approval-authorization+jws` and key ID `dsh-approval-authority/<configured identifier>`. Payload/header are JCS UTF-8; base64url is canonical/unpadded and signatures use 64-byte JOSE encoding. Key URLs, caller keys, duplicate/case-aliased fields, extra headers, private JWK material and DER signatures are rejected. A lease cannot be used as a phone decision or moved to another connection.

An authority trust anchor is configured independently of the peer delivering a proof. It pins issuer, key ID, P-256 public key/thumbprint, active state and an explicit validity interval. Signature verification fetches no URL. Key rotation/revocation requires replacing the configured trust set and closing affected caches. `approval.NewAuthorizationSigner` copies the configured private key into its own process memory, exposes only a copied public descriptor, and enforces its issuer/key validity. The optional entrypoint loads an explicitly configured protected PEM secret file; OS/HSM storage and automatic key-distribution trust are not supplied. Fixture keys are never production anchors.

`store.NewApprovalLeaseProvider` joins the transactional approval controller with a signer. `Issue` accepts the server-authenticated current host connection/key and transient actual context. It locks the current runtime/session, accepted approval, active user/device/membership and owner grant. The device approval/proof thumbprints and key version must still equal the recorded decision, as must the grant version. Current action and session/workspace scope are checked again. A regrant, refreshed phone token or another device cannot refresh the original decision's evidence. The stored phone proof is independently verified and must still match its canonical digest. A rejected decision may receive a proof of its recorded authority, but the host journal still denies execution for that decision.

Lease lifetime is positive and at most three seconds. Expiry is clipped to request, signed decision, original access token, original authentication-age limit, current grant, authority key and host heartbeat deadlines. Every date is UTC with millisecond precision; clipping rounds down. There is no future-issuance or expiry grace. Minting still uses the shared phone decision's 30-second issue-freshness rule. Once that window closes, this provider refuses further issuance; it does not silently rewrite or re-sign the phone decision.

The provider prepares audit/outbox metadata in the same transaction as its authoritative reads, signs while holding the relevant locks, and returns the proof only after COMMIT and a final expiry check. Any database/signing failure returns no proof. `approval.authorization.prepare` and `approval.authorization.prepared` describe preparation, not native execution or successful delivery. They contain IDs, hashes, versions and times; neither signed proof nor execution body enters these event payloads. A proof prepared near an expiry can still expire before delivery and must be rejected by its receiver. The control worker now acknowledges this preparation topic without treating it as an execution/delivery claim.

`verifyApprovalLease` / `approval.VerifyAuthorization` verify the pinned authority proof and its key/time window, exact context/connection, embedded registered phone key, phone signature and canonical decision digest. Only then is a plain internal `ApprovalAuthorization` constructed. Its assurance profile and authentication age must match the request, and lease expiry cannot exceed request/decision/authority/authentication deadlines. Pure verification grants no repeatable execution permission.

`ApprovalLeaseCache` is created for one host/installation/runtime/epoch/connection and one to eight pinned authority keys. It bounds concurrent verification and retained entries to 64, copies all accepted values, removes expired entries, and supplies synchronous evidence only for the same context/decision digest. Its `authorization` method is suitable for the journal's admission and final-guard authorizers. It never fetches authority or extends an expiry. Close clears all entries and fences in-flight results; a backwards or invalid clock closes it. Connection loss, account/key/grant revocation and plugin disposal must close this cache through the transport lifecycle when that integration is added. The journal still independently compares grant versions, checks live context/resource facts, persists one-use consumption and refuses replay after restart.

The shared schema now includes leases. `contracts/security/approval-leases.json` contains public-only Go/Node interoperability vectors, including valid allow/reject and malformed/boundary cases. Regenerate explicitly with `tsx tools/generate-approval-leases.ts` (`REMOTE_TEST_GO` overrides the Go binary). Fresh private keys exist only in generator process memory, so regeneration intentionally changes public keys/signatures. Both language suites verify all vectors. Go tests must use `-count=1` because shared fixtures live outside the Go module.

`npm run verify` includes host cache/journal tests and real npm DSH 0.2.1-rc.2 final-guard tests: a valid signed lease executes the protected fixture once; revoked/altered/expired leases do not. The native adapter uses a synthetic local authority, not a production school identity or mobile network flow. `npm run test:remote-dsh` also runs PostgreSQL provider coverage with race detection before the production Go + DSH session/question regression: exact original authority, expiry clipping, failed audit/outbox, changed connection/context and expired-token nonrenewal are tested in disposable databases. The server transport is implemented and separately tested with signed fixture peers; normal plugin wiring and Android still need to complete the end-to-end mobile flow.
