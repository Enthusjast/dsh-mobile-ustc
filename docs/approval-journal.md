# Host one-use approval journal

The host now has a durable approval state machine in the same private SQLite WAL database as command receipts. The existing key check, user-owned paths and AES-256-GCM key are reused with a separate approval AAD domain. `PersistentCommandJournal.approvals(runtimeEpoch)` opens one approval owner for that journal handle; it supplies no memory-only fallback or default authority.

The shared [main-database capacity](host-journal-capacity.md) defaults to 1 GiB and is reapplied on every open. Real SQLITE_FULL tests cover register, decision, final consumption and settlement: storage failure returns no new execution permit, and restart retains invalidated/unknown facts without replaying the old callback. WAL and filesystem quotas remain separate operational controls.

This is the host persistence/guard-consumption boundary. The [normal plugin](approval-native.md) now connects it to signed transport and the service lease provider. Native tests and the combined real CLI/Go test use local identity/model/key fixtures; they do not establish school identity, Android user verification or production acceptance.

SQLite schema version 2 added `approval_runs` and `approval_records`; [schema 3](approval-outbox.md) now adds durable report/acknowledgement metadata. Version-one command databases migrate only after their existing encryption key check succeeds; their encrypted command bodies/receipts retain the same AAD and remain readable. Missing key-check metadata cannot be recreated when either commands or approvals already exist. Older readers refuse unsupported schema versions. No automatic downgrade or evidence deletion is provided.

Full pending contexts, native IDs/call IDs, raw nonces, compact decisions and authorization records are encrypted. Plaintext storage is limited to routing UUIDs, runtime/boot IDs, hashes, state, times and a fixed outcome enum. Ciphertext AAD binds runtime, epoch, boot, approval, execution, context digest and context/decision purpose. An encrypted blob cannot be moved to another approval or substituted from the command journal. Record limits are 100,000 approvals and 64 active pending/approved/consumed records per runtime; contexts remain within the shared 128 KiB signing limit. Terminal nonce/execution tombstones are retained and not automatically evicted. Storage retention/archival and platform-wrapped keys remain deployment work.

States are:

```text
pending -> approved -> consumed -> settled
        -> denied
pending/approved -> expired | cancelled | invalidated
consumed without a trustworthy result -> outcome_unknown
```

`register` persists a validated current-runtime/epoch context before it may be published. Approval IDs, execution UUIDs and nonce hashes are immutable/unique within the runtime. The signature verifier runs before any decision is recorded. `decide` then obtains fresh current authorization and atomically commits one canonical decision digest plus encrypted evidence. Competing actors/choices conflict. Matching retries and equivalent ES256 encodings return the same stored decision while its proof/time/authority remain valid; they cannot replace it or reserve another execution. Invalid signatures or unavailable admission authority leave the decision digest unset. Status includes the separate signed-decision expiry; an unconsumed approval expires at the earlier request/decision deadline.

The trusted authority integration must provide a current owner `approval.decide` result for the exact runtime/epoch/session/approval/execution/binding, actor/device/key thumbprint/version, grant version, policy and required assurance profile/age. Internal evidence has a positive lifetime of at most three seconds, no future issue time and no expiry grace. **It is not a signed wire proof and must never be populated directly from a phone/WSS object or unverified IdP claims.** The [signed lease provider and verifier/cache](approval-leases.md) now construct this evidence after independent signatures and current authority checks; normal transport now connects them; production key provisioning still needs acceptance. There is no lexicographic assurance comparison or permissive fallback.

Decision admission bounds 64 in-flight operations and a 1.5-second deadline, passes an abort signal to the provider, and rejects late resolution after timeout/close. Providers may perform asynchronous work during admission. A final native `tools.guard` is synchronous, so `consume` requires a synchronous fresh authority lookup and rejects promises. It recomputes the actual execution/resource binding, checks the accepted decision expiry and exact current grant/key/assurance, then commits `approved` -> `consumed` with compare-and-set. Permission is returned only after the update really changed one row and COMMIT succeeded. Time is rechecked after authorization and after the commit: an expired lease/decision cannot be stretched by a slow SQLite write. A spent marker that cannot yield a timely permit becomes unknown without dispatch. A changed binding or unavailable/changed authority invalidates the unconsumed approval. The producer/guard must collect live resource facts; journal storage does not inspect files itself.

`consumed` is a spent permit, not proof that the tool body ran successfully. Another monotonic guard may still deny afterward; `settle` records the observed native result as succeeded/failed/cancelled and cannot rewrite a different final outcome. A SQLite write/commit error poisons further approval use through that handle. No ignored or failed update grants permission. Unknown results are not replayed.

Every attached approval owner has a fresh boot UUID in addition to the runtime epoch. Attaching another handle atomically replaces the active owner, invalidates old pending/approved records and marks old consumed records unknown. All old-handle mutations are fenced, even when an epoch is accidentally reused. Close invalidates only that handle's records and cannot close a newer owner. Reopening preserves terminal/audit records but never recreates callbacks, unspent permits or execution tokens. A backwards/non-integer clock fails closed until clock availability is restored.

Tests use actual SQLite, injected abort/ignored-update failures, key-check loss, cross-purpose/cross-record ciphertext substitution, concurrent owner decisions, asynchronous close/takeover, an authority that ignores cancellation, and an actual child process exit immediately after committed consumption. Recovery yields invalidated/unknown states. Plaintext scans cover database/WAL/SHM. Version-one receipt migration is exercised.

The installed npm DSH 0.2.1-rc.2 Tool Runtime tests connect native pre-execute/approval/guard/result seams to this journal through a test adapter. A valid committed decision executes a protected fixture once. Reject, altered signature, cancellation, revoked authority, changed file contents, failed storage and earlier auto-allow responders do not execute it. Signed authority leases are also exercised: valid executes once, altered/revoked/expired leases do not. Existing earlier/later final guards still deny; a spent permit followed by a later guard denial is recorded as a failed outcome. [Server decision audit/acceptance](approval-control.md) and the [signed lease provider/cache](approval-leases.md) are implemented internally. The normal plugin now offers signed approval when explicitly provisioned; production identity/key provisioning and the remaining capability/platform gates still need acceptance.
