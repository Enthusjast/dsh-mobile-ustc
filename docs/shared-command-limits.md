# 共享命令准入预算

生产入口使用 PostgreSQL 为远程命令尝试统一计数。用户、手机设备、安装和已有会话各有
独立预算；一个尝试必须同时满足适用的全部预算。相同主体的多条连接、多个服务节点、
Host owner 迁移、重新握手和 ticket 更新使用原计数，不按连接或 runtime epoch 重置。

覆盖 `message.submit`、`session.cancel`、`session.archive`、`session.model.select`、
`question.answer` 和 `session.create`。timed question 的持久答复复用 `question.answer`，
带文件消息也经过同一入口。创建会话时只使用前三种预算，不能伪造一个尚不存在的 session。
普通读取、订阅、审批决定/通知、文件 HTTP I/O、推送、身份登记和新连接准入有各自边界，
本功能不将它们计入共享命令预算，也不代替公网入口的身份/来源配额及拒绝服务防护。

## 默认值与部署

先应用迁移 `038_command_rates`，再部署服务。默认配置与
[`deploy/command-limits.example.json`](../deploy/command-limits.example.json) 一致：

| 字段 | 含义 | 默认值 |
| --- | --- | --- |
| window_ms | 每个主体窗口的毫秒数 | 1000 |
| user | 同一服务用户的命令尝试 | 60 |
| device | 同一手机设备的命令尝试 | 20 |
| installation | 同一安装全部 profile/使用者的命令尝试 | 120 |
| session | 同一会话全部使用者的命令尝试 | 20 |

这些是初始资源限制，不是已经测得的容量或延迟承诺。窗口在主体首次计数时建立，到期后的
下一次获准尝试重新建立窗口；窗口边界附近可能出现两批突发，不承诺 token bucket 式平滑。
`window_ms` 可设为 100–60000，各数量为 1–100000 的整数，`v` 必须为 1；四种预算取交集。

`REMOTE_COMMAND_LIMITS_FILE` 可指向仅当前所有者可读写的普通配置文件，例如 `0600`。
省略时仍启用默认策略。文件上限 8 KiB，拒绝未知/重复 JSON 字段、字段大小写别名、缺失字段、
null、非整数、零值和超限值。示例文件只作为模板，部署副本需按该保护要求保存。

可在不连接数据库的情况下核对期望配置和 RFC 8785 规范化 SHA-256：

```sh
# 在仓库根目录；二进制按服务 README 构建。
.local/remote command-limits describe
.local/remote command-limits describe --policy-file /受控目录/command-limits.json
```

首次启动保存策略与摘要，其他节点必须完全匹配。运行中每次配额事务也核对数据库中的策略
内容和摘要；配置冲突、策略缺失或数据库异常不会回退到本机/无限预算。未配置策略的嵌入式
Go 库夹具保留原接口行为；正式入口在监听前必须完成 `ConfigureCommandRateLimits`，不能用库夹具
构造方式代替生产入口。尝试配置后失败的对象也会拒绝命令，不静默退回未配置状态。

策略变更使用[离线状态查询和比较替换流程](command-limit-policy-operations.md)，先排空节点，
保留计数器，再按操作 ID 和旧摘要原子更新策略并留存审计。旧节点发现摘要不匹配后拒绝新命令。
不要通过删除策略或计数器来修改限制；预算已存在而策略缺失时，新节点也拒绝自行补建。
没有热重载或自动调参接口。首次上线时须排空尚不理解共享预算的旧服务节点，再恢复命令接入。
迁移 038 的 down 遇到任何计数记录均拒绝，不自动丢弃预算来回退；变更工具另需迁移 039。

## 事务和授权

配额事务先锁定并重新核对当前账号、登记设备与 proof key、组织、安装、runtime、grant
版本/范围和目标资源，并使用数据库墙钟检查期限。安装身份由目标 runtime 的真实归属解析，
不接受调用者提供其他安装 UUID。未获授权的资源选择器不会创建计数行。

计数器按用户、设备、安装、会话固定顺序加锁。在全部锁等待结束后读取数据库当前时间，
原子增加全部适用计数或全部拒绝。时钟倒退到某个窗口开始之前时失败关闭，不发放新窗口。
超额返回已有 WSS `rate.limited`，不会登记或转发本次命令。SQL 更新未覆盖全部计数行时也
失败并回滚，不能仅凭 UPDATE 没有报错就继续执行。

配额获准后先提交并释放数据库连接，再在命令事务中重新鉴权、检查期限并处理原 request ID。
配额不构成执行许可，也没有跨两个事务保留旧授权。因此同 ID 重试、内容冲突、随后业务拒绝
或命令审计失败，仍占用一次已提交的授权尝试预算。数据库提交结果未知时返回不可用，不自动
重做配额事务或执行命令；之后的显式原 ID 重试算作新的尝试。已存在命令的持久状态与去重
规则保持原样，不能用新 ID 掩盖未知结果。

当前 Host 报告已有命令结果、撤权通知和负向审批事实不消费这项预算，预算耗尽仍可持久对账。
计数器每种主体最多一行，并通过外键及匹配检查绑定已存在资源，大小由现有资源元数据数量
约束，不为任意请求 ID 或未知 session 建立临时键。只保存主体 UUID、窗口和次数，不保存
正文、参数、命令摘要、token、proof 或网络地址。这里的计数是运行预算，不是审计证据。

命令存储耗时指标的固定结果词表增加 `limited`，表示共享命令预算拒绝；它不创建主体、
策略摘要或资源 ID 标签，也不表示新的命令状态转换。

## 验证范围

隔离 PostgreSQL 测试覆盖独立 repository 共享四种预算、并发不超支、六类命令及附件入口、
冲突/重试/审计失败仍计尝试、未授权资源不污染计数、单连接数据库池不嵌套借用、窗口锁等待、
grant 期限、时钟倒退、配置冲突、运行中策略变化/丢失、部分 SQL 更新与迁移保护。

实际双进程 TLS/WSS 测试在第一个 owner 上消费预算，迁移到第二个 owner 并建立新手机
ticket/socket 后继续合用；超额正文不转发，已有命令结果仍可报告。正常本机 npm DSH
`0.2.1-rc.2` 双节点链路另验证真实原生会话、模型、提问、审批和撤权。身份及模型为本地夹具。
未进行 Android APP、真机、大负载或厂商通道测试；新增共享事务的目标负载成本尚未测量。
