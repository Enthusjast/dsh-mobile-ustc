# Android 应用更新页面

已登记手机可从首页进入「应用更新」。更新配置按[安装会话说明](android-apk-installation.md)单独打包，必须绑定当前学校登录部署与应用包名；缺少配置时只展示未配置状态，不从远端发行数据推导下载来源。元数据继续使用当前账号 / 设备的已认证 API，APK 下载则使用独立匿名 HTTPS 连接。

## 用户操作和状态

| 页面状态 | 可执行操作 | 安装边界 |
| --- | --- | --- |
| 检查中 / 暂无适用更新 | 检查当前设备适用发行 | 不把灰度未命中解释为所有用户已是最新版本 |
| 有适用更新 | 允许本应用安装，或下载并校验 | 来源设置与下载分别需要用户操作；设置返回不自动下载 |
| 下载 / 校验中 | 查看进度、取消或返回 | 暂存和未提交会话在离开后清理 |
| 已校验 | 打开系统安装确认 | 再次查询原发行和当前身份，提交原会话 |
| 等待系统确认 | 明确继续，或核对结果 | 保持原发行 / session；新页面不会自动弹出确认 |
| 结果未知 | 核对当前安装、明确放弃 | 只读核对不会再次 commit 或创建新会话 |
| 已安装 | 查看核对结果、检查后续发行 | 依实际已安装包和完整摘要，不依赖成功回调 |
| 其他账号 / 不可读记录 | 明确放弃旧更新 | 隐藏旧发行和账号细节，清理只作用于本机更新 |

服务声明当前 version code 不在支持窗口时，页面显示对应提示，仍按服务公布的适用发行处理。不新增静默强制更新、卸载重装或自动降级政策。

## 账号、发行与生命周期

`AppUpdateFlow` 每个前台页面拥有独立的 view id。它通过 `AppUpdateAccess` 调用受限 Android 适配层，不暴露任意安装包路径、下载地址或通用安装接口。

进入页面可自动读取当前元数据；下载前重新查询，并要求与用户看到的完整原发行一致。准备完成后，`AppInstallations.commit` 调用挂起的授权回调，重新查询当前账号 / 设备适用的发行，并确认原包名、已安装版本、签名和更新配置仍相同。异步系统确认提示送达后，打开前还要重新确认原发行。发行撤销、灰度 / 说明变化、版本变化或认证失败都会拒绝继续，不静默换成另一个候选。

`LoginController` 绑定账号代次、页面代次、设备、登录有效期和前台状态。导航、注销、凭据更新或切到后台会关闭更新页的操作作用域，作废排队事件、关闭私有候选，并退役未提交会话。已提交或结果不明的尝试保留原记录，返回前台时先重新核对实际安装，用户明确继续才恢复原等待确认流程。重建后的未提交 PREPARED 记录不能代替丢失的私有候选关联；页面要求重新准备。

页面按钮携带渲染时的 view id、原发行摘要和安装尝试 ID；清理确认框另外固定该次记录的匿名关联摘要。旧按钮或确认框不能转移到新页面、新发行或新安装尝试，也不会因为拒绝旧操作而退役当前有效候选。确认上下文变化后，旧清理对话框关闭。

系统设置 / 确认通过 Channel 传递一次性事件，`MainActivity` 只在 STARTED、当前账号和当前更新页都有效时消费。Intent 固定到系统组件。接收器和 StateFlow 状态不会直接打开 Activity；已消费或属于旧页面的事件无法在新页面重放。首次安装请求只在 30 秒的当前前台意图窗口内等待异步确认提示，过晚送达只显示待确认状态，需用户再次点击。

APK 下载保持原有的完整长度、SHA-256、包名、版本、最低 SDK 和本机当前 signer 校验。发送给系统的原会话使用经过校验的写入 / fsync 关联，API 26 不依赖受 SELinux 限制的暂存文件读取；具体限制见[安装后端](android-apk-installation.md)。系统回调只触发核对，不能单独使页面显示安装成功。

创建、提交、放弃、清理和安装确认使用统一的安装操作锁。排队的清理取得锁后仍检查当前协程和调用者，在每次放弃与重置记录前重新检查，避免旧页面清理穿过新页面的准备操作。结果回调继续使用存储 revision 约束；与只读安装核对并发时的普通冲突保留待核对状态，不据此确认或重放安装。

## 验证入口

`AppUpdateFlowTest` 使用独立平台边界验证发行变化、权限事件、取消、旧页面事件、未知结果、独立安装事实、账号退役和晚到确认；不把这些状态测试当作真实 APK 安装证据。`AppUpdatesScreenTest` 检查明确操作、清理确认、账号页面变更、深浅色、小屏 / 横屏及大字体。截图只导出合成的公开发行夹具。

`AccountAppUpdateTest` 使用真实本地 TLS / OIDC / DPoP、AndroidKeyStore、匿名下载、平台验签和 PackageInstaller。覆盖准备后撤销发行、前后台切换、注销期间的晚到响应、最后一次授权查询期间注销、重算元数据摘要后的签名篡改、旧确认事件作废和缺少更新配置。只生成系统待确认请求，始终不批准候选；十个微型 APK 都没有可执行应用代码，不能用来证明工作应用完成自升级。

```sh
cd android
./gradlew check :app:assembleDebug :app:assembleDebugAndroidTest
cd ..
python3 tools/integration/run_apk_update_preflight.py \
  --serial emulator-5594 --avd dsh-remote-api26 \
  --installer-fixture --update-flow-fixture
```

新增开关要求专用 AVD 已配置安全锁屏、登记指纹并解锁，才能执行真实账号密钥夹具；不放宽生产密钥策略。默认主 APK 仍不包含学校、更新、推送测试配置或候选文件。厂商推送和学校生产配置仍未就绪，本阶段沿用本地夹具。真实来源设置往返、完整应用自更新、升级后业务数据兼容、公网下载及目标 OEM 验收需要独立记录。
