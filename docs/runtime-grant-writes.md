# Runtime 授权写入与手机撤销

`PUT /v1/runtimes/{id}/grants/{user_id}` 和同路径 DELETE 在授权事务内重新核对当前手机。
HTTP 中间件中的设备查询只提供请求入口检查，不能替代提交授权变化时的检查。

事务使用已验证的 issuer/subject、设备 UUID 和 JWT 绑定的 DPoP 公钥指纹，检查账号活跃、
设备属于该账号、指纹匹配、设备未撤销，并对账号及设备行加共享锁直到提交。随后按现有规则
检查组织成员关系、runtime/安装/Host 和当前管理权限。数据库处于恢复隔离时拒绝写入。
不存在、他人或已撤销的设备，以及不同的公钥指纹均被拒绝，不依赖审计外键间接挡住操作。

授权写入和设备撤销按实际锁顺序完成：

- 设备撤销先取得设备行锁时，授权事务等待它提交。SERIALIZABLE 旧快照被 PostgreSQL 中止后，
  服务端重新开始完整事务并检查当前设备，最终拒绝该授权写入。
- 授权写入先取得设备共享锁时，设备撤销等待该事务提交；完成撤销后，该设备不能再执行新的
  授权写入。先前已经合法提交的其他用户授权仍是独立记录，不因授予者手机遗失而自动撤销。

相同内容的 PUT 和已经撤销记录的 DELETE 重试也必须经过当前权限检查。幂等结果不是持久
管理凭据，不允许已撤销设备通过旧请求重新授予权限或查询成功回执。

## 锁等待与授权到期

SERIALIZABLE 的 `now()` 固定为事务开始时间，不能用它判断等待锁之后是否仍有管理权限。
服务端在读取 owner grant 时使用数据库 `clock_timestamp()`，保存本次取得的原始管理期限；
取得目标授权行锁之后，以及审计/outbox SQL 完成、准备提交之前，再按数据库当前时间检查。
管理权限已经到期则返回 403 `access.denied`，回滚本次授权、版本、审计及事件；相同内容的
幂等请求也遵守该期限。最后一个有效 owner 的检查同样使用数据库当前时间。

PUT 请求中若指定的目标到期时间在等待期间已经过去，返回 400 `grant.invalid` 并回滚，
不会把请求开始时有效的到期时间当作可继续创建的授权。客户端可刷新当前权限和时间后，由
用户决定是否提交新的有效请求。当前组织管理员使用独立的管理角色，不因其另一条 owner
grant 到期而失去管理员权限。

期限复核保留操作开始时取得并锁定的管理依据，因此有其他有效 owner 时，仍可明确降级或
撤销自己的 grant。它不会在修改自身记录后因 role 已改变而错误拒绝原本合法的操作。已经
合法提交的其他用户授权继续按其自身期限和撤销状态生效。

提交前检查是数据库事务的授权决策点。数据库提交、网络响应或已开始的外部操作可能晚于该
时刻；本接口不把响应到达时间当作权限生效时间，也不保证回收先前合法提交的授权。

## 中止与重试

两个操作保持 SERIALIZABLE 隔离，并复用有界数据库事务重试：最多 16 次尝试、单次锁等待
上限两秒、整个操作最多十五秒且遵守调用者取消。仅 PostgreSQL 明确返回 `40001` 或 `40P01`
时重做完整事务。每次先回滚失败事务，再重新检查设备、账号、成员关系、管理角色、范围和目标；
失败尝试中的版本、授权、审计和 outbox 均不保留。普通业务拒绝、存储错误及提交结果不明
不会自动重做。错误响应只包含固定错误代码，不包含数据库异常、请求正文或凭据。

PUT 只使用路径中确定的 runtime/用户和严格的授权 JSON；DELETE 不接受正文。两者均拒绝
查询选择器。HTTP 接口未改变授权 JSON 或成功响应格式，不需要数据库迁移。内部 Go store
及 Repository 接口增加显式 `proofJKT` 参数，调用者必须传入经过验证的当前 DPoP 绑定，不能
用查出的任意设备指纹填充。运行中的旧节点仍保留旧检查边界，部署时需更新所有控制面节点。

真实隔离 PostgreSQL 测试使用实际 `RevokeDevice` 和行锁等待验证两种并发顺序，并覆盖当前
密钥不匹配、其他账号设备、缺失设备、幂等请求重新鉴权、确认中止后的原子重试、普通审计失败
不重试和回滚。HTTP 测试检查验证后的指纹确实传入事务接口，以及 Host 客户端、无效选择器
和 DELETE 正文被拒绝。本机 npm DSH 0.2.1-rc.2 组合继续验证原有撤权、审批许可失效及连接
断开路径。身份和模型使用本地夹具，Android APP、本轮真机、大负载与厂商推送不在验证范围内。

到期回归先在旧实现复现 PUT、DELETE 和两种幂等请求越过管理期限仍成功的时序；修复后通过
真实目标行锁等待及审计触发器等待，验证管理期限/目标期限到期时整体回滚、管理员独立权限
及合法自我撤权。时间等待依据 PostgreSQL 当前时钟，不修改全局时钟或生产租约。
