# 本人设备目录与遗失设备撤销

`GET /v1/devices` 为当前学校账号列出已登记的手机设备，包括已撤销记录。调用方必须使用
有效资源 JWT、匹配的 DPoP proof 和当前活跃的已登记手机密钥；未登记/已撤销的密钥、停用账号
和 Host OAuth 客户端不能枚举目录。它不要求 runtime grant 或组织成员关系，方便用户在失去
业务授权后仍管理自己的设备。

```http
GET /v1/devices?limit=50
Authorization: DPoP <resource-access-token>
DPoP: <fresh-proof>
```

响应的 `data.items` 包含 `device_id`、`name`、`key_version`、`state`、`is_current`、
`created_at`、`last_seen_at` 和 `revoked_at`。状态为 `active` 或 `revoked`，两个可空时间保留
实际数据库值；没有活动时间时不伪造。名称是用户提供的展示文本，不是设备在场或硬件身份的
证明。设备条目不包含公钥、指纹、连接秘密、token 或推送地址，也不会列出其他账号的设备。

## 分页与授权

默认每页 50 条，最多 100 条。顺序为创建时间倒序，再按 UUID 倒序；相同时间的设备也有确定
边界。有后续页时返回不透明 `next_cursor`，否则为 `null`。下一页传入
`?limit=50&cursor=<next_cursor>`。只支持这两个可选参数，重复参数、未知选择器、空游标、
非规范 limit 或 GET 正文均返回 `protocol.invalid`。

游标只定位当前账号的元数据，不是权限凭据，也不是历史快照。它绑定生成时的服务用户 UUID
和当前 DPoP 公钥指纹，编码内容是上下文元数据而非秘密；同一密钥刷新 token 后可以继续使用，
账号或密钥切换后应重新分页。
每页在同一数据库语句中重新检查当前账号和手机密钥，再读取有界结果，不能靠前一页的检查
继续读取已被撤销的身份。

分页期间登记、名称或撤销状态可能变化，返回的是各页查询时的当前状态。需要查看最新登记时
重新从第一页开始；不要将整段分页当作一个固定事务快照或当前业务授权证明。迁移
`033_device_directory` 增加用户、创建时间与 UUID 的组合索引，不改变授权或存储内容。

## 撤销

用户从本人目录核对目标后，向既有 `DELETE /v1/devices/{id}` 发送新的认证请求。服务端仍独立
校验目标属于当前账号，并将撤销、审计及 outbox 在同一事务提交；重复撤销保持幂等。撤销另一台
手机不撤销当前手机。撤销当前密钥后，后续目录和业务请求会被拒绝；本地清除账号与服务端撤销
是不同动作。

该接口为后续客户端设备管理提供后端能力，本轮没有改动 Android APP。旧主机安装另有
[安装发现与撤销入口](installation-management.md)；真实学校目录/设备验收仍需另外完成。

## 本地验证

小型 PostgreSQL 测试覆盖同时间分页、本人和其他账号隔离、游标换账号/密钥拒绝、当前撤权
重检、无组织或 runtime grant 时列出本人设备、敏感字段排除及列出后幂等撤销。
HTTP JWT/DPoP 测试覆盖匿名、Host 客户端、未登记设备、错误查询和数据库失败。
Go/PostgreSQL/本机 DSH `0.2.1-rc.2` 双节点夹具使用实际目录分页取得另一手机 ID，撤销其
在线连接，并验证主手机继续读取会话；响应按 OpenAPI Schema 校验。身份和密钥均为本地夹具。
