# Go / DSH integration evidence

On 2026-10-24, `npm run test:remote-dsh` passed with the real Go `cmd/remote` entrypoint, an isolated PostgreSQL 18.6 cluster, and the installed npm DSH 0.2.1-rc.2. The plugin uses the same DSH session controller and Agent for local IPC and outbound Relay traffic. No TokenWorks process is involved.

Run from the repository root:

```sh
npm run test:remote-dsh
```

The Python runner creates a temporary private directory, initializes an unprivileged PostgreSQL cluster with no TCP listener, applies the migrations, builds the Go executable and host plugin, runs all Go tests with race detection/cache disabled against private databases, then runs the TypeScript integration. It always stops that cluster and removes its directory. It does not accept a database URL or use the existing PostgreSQL service. Go and PostgreSQL binaries must already be installed; use `REMOTE_TEST_GO` and `REMOTE_TEST_PG_BIN` when their paths differ from the local defaults. Run under an unprivileged account with Node/npm, Python 3 and the repository dependencies installed. The ordinary `npm run verify` remains independent of PostgreSQL.

The test seeds only three identities and organization membership through SQL. Before device enrollment it checks that authenticated `/v1/me` returns the correct internal user UUID and organization role, ignores caller-supplied identity selectors, denies an unprovisioned/suspended user and reflects removed membership. The fixture restores its membership/status before proceeding. All subsequent device registration, enrollment and credential/ticket operations use the HTTP API with locally generated ES256 access tokens, DPoP nonce retries and registered-key proofs. Host and phone confirmations are separate calls. A third user with membership but no runtime grant cannot obtain a ticket or list that runtime.

The Go/PostgreSQL suite also checks the account lookup with identical subjects under different issuers, two organizations, membership changes/removal, inactive users, empty-array encoding and a database outage. A read does not provision users, devices or grants. The HTTP suite checks nonce-authenticated pre-enrollment access, no-store responses and denial without account disclosure on database failure. These checks passed in the same isolated-cluster race run on 2026-10-24.

The test opens the real host and mobile WebSocket connections, waits for the DSH catalog to appear through the PostgreSQL-backed directory, creates a session through Relay using an authorized workspace UUID and configured preset, then checks a snapshot, native events, assistant chunks, persisted command receipts, a replacement sync and fixed-cursor pagination. Repeating the creation request UUID returns one native session; unknown workspaces/presets are denied and changed creation content conflicts. Repeating the message request UUID produces one native user message; changing its body conflicts. Wrong pagination cuts require resynchronization. [Remote cancellation](session-cancel-protocol.md) interrupts a held model call, preserves interrupted partial output, rejects stale epochs and returns a durable settled status on retry. Unsubscribe releases the follower. Revoking an idle sibling device closes only that device; the primary phone can still page history. Revoking the primary phone user's grant while an approved Bash call is held after guard sends `access.revoked` and closes the socket within five seconds, prevents new tickets, and acknowledges supported control events. The host blocks the held body and reports invalidation before lease expiry. Session content must stop after the ordered revoke notification; frames queued before revocation can still arrive during the DELETE round trip.

A database dump is checked for absence of the unique prompt, model reply, local workspace path, enrollment code, raw host credential and mobile ticket. PostgreSQL still contains the intended command IDs, states and canonical digests. The test also exercises graceful service shutdown with upgraded sockets.

Two simultaneous sockets use the same registered phone key with different workspace tickets. The socket scoped to another workspace must stay connected and receive no command receipts from the active workspace. This covers receipt metadata as well as the separate session-content subscription checks.

The native blocking-question tool publishes its pending list through the session subscription. An invalid option returns a rejected receipt while preserving the question; two registered phones then compete to answer it, with exactly one accepted result. A matching retry returns the stored status. The question disappears, the native turn finishes, and the dump excludes both the question and unique answer text. See [blocking-question protocol](question-protocol.md). A separate fixture preset uses the installed native timed tool and verifies [timed claims/releases and late answers](timed-question-protocol.md), including unattended continuation, retired claim-ID denial, a durable late reply and matching retry.

The identity issuer, model adapter and host credential/key provider are local fixtures. The test does not validate school IdP registration, PKCE, real model access, OS key storage, Android merging/cache or a production TLS ingress. Single-process outbox propagation and periodic authoritative connection checks are implemented; see [revocation evidence and deployment limits](revocation-propagation.md). Mobile lease renewal, durable multi-node fanout and target-load/failure-window measurements remain separate gates. This is combined Go/PostgreSQL/DSH evidence, not a production readiness or Android acceptance claim.

The Go suite now includes a separate PostgreSQL/HTTP/WSS signed-approval composition test. It uses real JWT/DPoP middleware, registry/owner policy, decision signature verification, transaction audit/outbox and a signed three-second authority lease. Authenticated fixture peers cover weak assurance and modified signatures without spending pending state, valid forwarding, final failed-result metadata, offline status reconciliation and stale-grant denial. This fixture-peer test does not run a native tool or wire the normal DSH approval callback. The CLI chain additionally provisions the normal factory, obtains the current Bash context, rejects a changed signature without consuming pending state, allows one actual sentinel write, verifies idempotent decision retry, rejects/cancels without dispatch and observes durable native results. The database dump excludes each command/argument marker. See [native ownership and its remaining gates](approval-native.md).
