# Host 连接队列、断线与原命令对账

Host 接收队列同时限制为最多 32 个待处理帧、512 KiB 原始编码字节，单帧仍最多 64 KiB。
限制在入队之前检查，出队时释放字节预算。这个预算只覆盖 Host 入站待处理帧，不代表
WebSocket 实现缓冲、原生会话、文件、订阅队列或进程总内存已经完成容量验收。

读取队列的终止条件包括 transport close/error、binary/超长帧、队列预算超限、读取超时和
连接取消。终止立即清空待处理帧，拒绝当前/后续读取，取消该连接的 signal 并终止 socket；
后续 message 事件不能重新向已结束队列追加。已解析但尚未处理的帧也要再次检查生命周期。
server.draining 一经处理立即退役该连接，不再接受其后排队的命令。

旧实现只保存队列错误，`next()` 却先出队再检查错误；message listener 在队列结束后仍追加，
在途 dispatch 还不会因 socket close 收到取消。慢处理可能让队列继续增长，并把旧帧送到原生
运行时。现在终止路径优先于缓存帧，断线/预算超限不会等待慢 dispatch 后才通知取消。

接收循环同时将当前 handler 的等待绑定到连接 signal。原生或外部实现即使暂不响应取消，
也不能阻塞连接退役与重新握手。握手 signer 的等待同样受连接取消约束；晚到的签名或命令
回执仍只属于旧 socket，不会转投新连接。这里中断的是网络 owner 的等待；**不承诺终止
不配合的原生调用、撤销已发生的外部副作用或恢复未提交日志**。

重新接入仍经过退避、`HostCredentialProvider.acquire(signal)` 和当前安装密钥的全新 challenge
证明，重新发布 catalog。旧入站队列和旧订阅不会迁移，手机需要新的 subscription/sync。
纯连接重建不改变仍在运行的 DSH runtime epoch，也不创建新 Agent 或自动重发命令。

连接丢失可能发生在本地 journal 提交、原生准入或回执之间。已有本地记录和副作用不能被
“连接取消”当成未执行。原 request_id 的显式重试继续沿既有 journal 去重/原生对账规则：
已入队的原消息恢复 agent_queued，不再调用 prompt；不明确的结果保留 unknown。
新连接收到晚回执也不能据此让旧调用重新取得执行授权。

## 账号取消与插件资源

发行端应在登出、切换账号或安装身份结束时取消凭据 provider 的 `signal`；已登记入口把
资源账号、登记客户端、绑定存储和凭据 provider 的生命周期合并。该信号终止后，插件卸载
自己专用的 Cordis 子作用域，停止新的命令准入、取消待答交互、关闭 Relay/本机调试 socket
及读取订阅、关闭加密命令日志，并移除问题/审批监听器和工具执行检查。父作用域和原生
DSH Agent 保留，既有原生会话仍可由宿主按自身权限使用。

旧实现仅令 Relay 退出，启动后的本机 socket 和交互监听器会一直保留到整个插件卸载。
现在账号取消使用完整资源作用域清理；仅关闭 socket 或标记 runtime closed 会遗留监听器，
因此也不足以完成账号退休。直接调用公开 `apply` 时同样创建子作用域，不会为清理插件而
dispose 调用者的整个 Context。父插件在异步启动期间卸载时，在线检查/密钥封装也及时取消，
不等待不配合的外部 Promise。文件清理失败时仍会尝试关闭日志并清零其内存数据密钥。

普通断网、Relay drain 或连接租约到期仍按原退避流程重连；它们不代表账号已经结束。
服务端撤销某 runtime 也不能替代发行端的账号退出通知。账号 signal 一旦取消，不会自动
复活旧运行实例；新账号或新的登录生命周期需由发行端明确重新加载，重新核对绑定、创建
新 epoch 并握手。第三方 source、OS 签名器与存储对象仍由其创建者负责关闭。

这些清理不会重放旧命令、回滚已开始的外部副作用或删除持久日志，也不宣称注销了 IdP 会话。

## 原生操作前的取消边界

Host runtime 为命令、读取订阅和定时问题 claim 合并调用者 signal 与自身生命周期。
`runtime.close()` 主动取消这条生命周期，且可幂等调用。命令在回执通知等待后、即将进入
原生分发时重新检查；会话目录/身份解析、模型目录和归档活动检查返回后也再次检查，避免
一个不响应取消的异步读取恢复后，让旧请求取消 Agent、归档会话或改变模型。

DSH 适配器的 `create`、`cancel`、`archive`、`modelCatalog` 和 `selectModel` 可接受调用者
signal；受限协议入口始终传递当前 runtime 的合并 signal。文件/消息等原有 signal 检查
继续适用。取消检查位于原生操作准入边界，不承诺撤销已经进入原生服务的写入或外部副作用。

原生调用已经返回确定结果时，后来的取消不会把结果改成“未执行”。日志仍按已有持久性规则
保存已知结果；检查点失败或原生结果不能确定时继续保留 unknown。不会因为网络 owner
结束，就用新 request ID 自动重放。若日志已随账号清理关闭，未完成的原记录仍须按持久事实
恢复和对账，不能由一次取消推断执行结果。

真实 DSH Loader 回归在旧实现复现：会话 inspect 晚返回后执行原生 cancel（分别取消请求或
runtime）、归档活动检查后仍归档、模型目录后仍选择，以及等待 dispatching 回执期间取消后
仍创建会话。修复后这些调用均未进入对应原生操作。另验证原生 cancel 已完成、应答晚到时，
仍保存一次 settled 事实。夹具只阻塞这些异步边界，不修改系统时钟、模型权限或原生接口。

专用本机组合：

```sh
REMOTE_TEST_DSH_BIN=/本机安装路径/dsh \
  python3 tools/integration/run_host_enrollment_terminal.py --host-account-retire \
  --output .local/host-account-new-run.log
```

它先完成普通 Go/PostgreSQL/DSH 业务链路，再取消正常已登记插件的测试账号 source。
原 IPC 和 Host 连接关闭后，同一个 npm DSH Agent 仍完成新的原生持久化检查点；服务端
账号与安装仍活跃。本机控制文件和检查报告仅属于隔离测试，不是产品管理接口。此模式与
五分钟续期、整套安装撤销分别运行，学校登录退出/切换通知和实际发行集成仍需另行验收。

## 租约与换证

Host 现在独立约束 hello 中的连接期限，不依赖 Relay 最终关闭 socket。有效 hello 必须使用
v1 的 20 秒 heartbeat 与 64 KiB 帧参数，protocols 不重复并包含所选 v1，capabilities 不重复
且只能从本次 Host 提供的集合选择。旧 peer 可以继续省略可选扩展，不能选未提供的能力。

server_time 与 Host 墙钟最多相差 30 秒，expiry 必须晚于双方当前时间，声明的
expiry − server_time 最多五分钟，与既有 Host 连接凭据一致。客户端取本地绝对到期和
server-relative 剩余量中较短者，再同时用墙钟与单调时钟约束；时钟回拨不能延长原权限。
计时器与接收/发送检查独立执行，到期立即取消连接及其 owner，不等待当前 handler 返回。
pong、业务流量和新的审批授权证明均不能重置这条连接的原始期限。

到期后仍通过 provider 再次获取凭据、完成新 challenge，而不是在旧 socket 内更新权限。
可使用现有 Go API 的[REST provider](host-credential-provider.md)取得有效新凭据；它仍依赖
已经验证的资源登录态与安装 signer，不代表学校 token 刷新或 OS 私钥存储已经实现。
如果 provider 返回已经到期的原值，Relay 仍会拒绝，不在客户端静默延长或绕过认证。

退避基数从一秒指数增加到最多 60 秒，每次额外加入少于基数 25% 的随机等待。
通过握手且 transport 持续至少 30 秒后，下次重连重置为一秒基数；短暂成功/快速抖动不会重置。
旧逻辑只在接收循环正常返回时重置，而关闭通常走异常路径，会让稳定连接的多次正常换证
逐步积累到最长等待。稳定性判断使用单调时钟，只描述 transport，不代表目录/业务全部健康。

租约补充在修复前还复现了短租约不主动结束，以及七类不兼容 hello 被接受；修复后的短租约
peer 保持 socket 打开并发送 pong，Host 仍结束在途 owner、丢弃旧队列、重新获取凭据并握手，
之后只接受显式新命令。可控时钟组件测试覆盖双方时差、五分钟边界、墙钟前跳/回拨、
单调期限和异常时间；可控退避时钟验证 30 秒稳定窗口后的重置及抖动/上限。
这些时间变化是组件夹具，不是修改系统时钟或真实设备的长时间续期验收。

## 小型夹具证据

三个真实 WebSocket 回归在修复前失败：第一条 dispatch 等待时，主动关闭 transport、
发送 34 个小帧，或发送 10 个约 60 KiB 帧，均未及时取消原连接。修复后它们验证在途
signal 取消、缓存命令丢弃、第二次获取凭据、新 connection/challenge 以及只接收显式新操作。
这些是队列边界用例，不是大负载或重连风暴测试。

额外用例覆盖 signer 不返回时关闭、dispatch 忽略取消时仍可重连、晚签名/回执不能跨 socket，
以及 draining 后的尾随命令丢弃。实际 npm DSH 0.2.1-rc.2 Loader 组合主动断开已入队命令的
Host transport，检查新的证明/catalog、相同运行代次、没有自动重发，随后显式重试原 ID：
回执恢复 agent_queued，新 sync 的原生日志仍只有一条对应 user/message。

身份、模型和 Relay peer 是本地夹具。普通生产 Go/PostgreSQL 双节点 DSH 链路另外验证兼容性。
没有使用 TokenWorks，没有进行大负载、真机或厂商推送配置；所有旧未知结果仍需持久事实对账。
