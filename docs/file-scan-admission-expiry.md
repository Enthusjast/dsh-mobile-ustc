# 文件扫描租约与发布的提交前检查

扫描领取、续租、完成及失败回执在状态/对象账本写入、触发器、审计和 outbox 等待之后，
提交前再次使用 PostgreSQL `clock_timestamp()` 检查扫描窗口、保留期限及租约。领取、
续租和 clean 发布还重新检查已锁定上传/下载 grant 的到期时间。行锁固定版本和资源，
不会阻止时间流逝。

领取与续租读取数据库实际返回的租约，并按文件、保留期和 grant 的较早期限裁剪。续租
同时检查原租约，不能通过一次延迟更新使已过期任务复活。完成时保留原来的 scanning
期限参与最终检查，不能因本次 UPDATE 将文件期限延长到 retain_until，就掩盖原扫描
窗口已经到期的事实。正常三十秒扫描租约、三次尝试上限和对象键规则保持原样。

期限检查失败时整体回滚文件状态、原始/候选对象指针、attempt、重试次数/计划、清理期限、
成功审计及 `file.clean` / `file.export.clean` 引用。领取不返回 candidate，续租不返回新
期限，完成不报告 clean；数据和审计不会出现本次局部更新。grant 到期沿用
`files.ErrAccess`，扫描/保留期/租约到期沿用 `files.ErrStale`，数据库失败沿用
`files.ErrUnavailable`。

关键单行账本写入、文件系统审计和 clean outbox 插入还要求实际影响一行。INSERT/UPDATE
被忽略时拒绝提交，不能把仅创建了部分扫描证据的事务报告为成功。未提交 candidate 尚未
交给 I/O worker；已经写入存储的候选字节继续由已有对象账本和垃圾回收规则追踪，不声称
元数据回滚撤销了外部 PUT。

失败回执可以记录 access_revoked，不需要重新取得已经失去的用户 grant，但仍必须属于
原有效扫描租约和文件窗口。过期任务不能写入新的失败/重试事实；下一次领取及过期清理
仍按原有接管、退避、对象键和删除证据处理。

已经提交的相同 attempt 的 clean 完成重试是历史对账，即使原租约到期或原设备已撤销，
也只确认原完成事实，不重复审计、发布、延长截止时间或恢复扫描授权。新的续租、下载和
交接继续要求当前权限。提交前检查是准入决策点，不承诺权限持续到 COMMIT 或网络响应
到达之后。

## 验证

隔离 PostgreSQL 先复现 27 个越期提交场景：领取、旧/新租约续期、完成状态/审计/outbox，
以及失败回执跨过各自独立期限。修复后使用真实锁等待和数据库墙钟核对事务前后的文件、
transfer、attempt、对象账本、审计与发布引用，确认全部回滚。夹具只缩短测试行期限，
不修改系统时钟或生产 TTL。

17 个写入忽略场景分别验证关键账本和事件缺失时失败关闭，恢复写入后可重试；另验证
已撤销设备的历史完成对账不写入新事实，也不能续租。原有并发领取、错误 lease/policy、
接管、撤权、有限重试、审计/提交失败、文件 I/O 与 Host 交接回归继续运行。

完整 Go race/隔离 PostgreSQL 与本机 npm DSH `0.2.1-rc.2` 双节点终端链路分别验证。
对象存储、扫描、身份和模型为本地协议夹具；本轮不修改 Android APP，不运行大负载、
真机或厂商推送配置，也不宣称真实病毒引擎、学校生产或目标 SLO 已验收。
