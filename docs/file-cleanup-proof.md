# 文件删除领取、回执与配额证据

文件过期只终结其访问资格，不直接归还配额。后台 worker 必须取得独立删除租约、按账本
重构并核对对象键、完成对象服务 DELETE，再提交删除确认。所有追踪键都已确认删除后，
才原子记录配额归还并扣减 organization/session/user 三类逻辑预留。

## 领取与活跃候选保护

GC 现在先用 `SKIP LOCKED` 锁定 file/transfer，再用独立的 READ COMMITTED 查询重新
检查到期对象、删除租约、文件状态、committed attempt 和活跃扫描，最后锁定对象行。
锁顺序与扫描及删除确认一致，繁忙记录留给下一批处理。

不能仅用锁对象之前的快照判断“旧扫描租约已到期”。扫描续租可能已经在截止前完成准入
检查，仍持有文件锁等待 COMMIT，其他快照只能看到它已经到期的旧租约。旧实现会给这个
候选对象发出删除许可。文件锁与随后的新快照共同避免把仍在提交的续租/发布误当成垃圾；
当前 clean 候选和有效扫描候选继续受保护。

删除领取读取数据库实际保存的截止时间，提交前按数据库墙钟复核。租约写入被忽略或在
等待期间到期时不返回删除许可。I/O 组件在调用存储 DELETE 前还检查父生命周期和原有
一百毫秒租约余量，不把已经不可用的任务交给存储实现。

## 回执与配额

删除成功/失败回执在对象状态、配额锁、各类配额更新、归还标记及审计写入后，提交前
重新检查原租约。到期会整体回滚 deleted_at、失败重试计划、lease 字段、配额和审计。
不能因为实际 DELETE 发生过，就使用已经失效的租约覆盖当前清理事实。

明确的单行过期状态、删除租约、删除回执、配额扣减及归还标记都要求实际落库；被忽略
的写入返回 unavailable，不能报告成功。重复/旧回执继续返回 stale。只有最后一个对象
的有效确认可消费空的 quota_released_at，一次归还只产生一次审计。已经归还的键仍保留
每日对账计划，重复删除不会再次扣减配额。

元数据失败不撤销对象服务已经完成的 DELETE。回执过期或结果不明确时，之后的 worker
取得新租约再次确认删除，按原有幂等对象删除与账本规则处理。逻辑配额不等同于物理磁盘
占用；延迟 PUT、对象服务生命周期、KMS 和生产容量仍由既有存储边界负责。

## 验证

真实隔离 PostgreSQL 先复现：有效续租在 COMMIT 中等待时 GC 错领候选，以及七个领取/
确认/失败/配额/审计等待后越期成功的场景。修复后用延迟约束触发器、真实行锁和数据库
墙钟验证保护与回滚；不修改系统时间或生产三十秒删除租约。

11 个写入忽略场景覆盖过期、领取、回执、三类配额、归还标记与审计；恢复写入后可重试。
并发领取只产生一个同键租约，并发确认只消费一次删除证据。组件分别验证过期、余量不足、
取消和有效租约，失效任务的存储调用与成功回执次数均为零。

完整 Go race/隔离 PostgreSQL、go vet 与本机 npm DSH `0.2.1-rc.2` 双节点正常链路分别
回归。对象存储、扫描、身份和模型为本地协议夹具；本轮不修改 Android APP，不执行
大负载、真机或厂商推送配置，也不声明生产存储和 GC 时延 SLO 已验收。
