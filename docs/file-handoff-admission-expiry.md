# 文件交接许可的提交前期限检查

扫描为 clean 的对象仍须经过当前上传授权、安装密钥和 Host 连接校验才能交接。文件交接
签发、续租、读取票据消费和 staged 确认在资源锁检查之后、事务提交前再次使用 PostgreSQL
`clock_timestamp()` 复核期限，覆盖状态写入、触发器、审计和完成标记的等待。

最终检查同时核对原 Host 凭据、文件、上传 grant、交接期限及本次租约。续租还保留旧租约
期限，旧租约若在更新等待期间到期，即使新期限仍在未来也不能提交续租。签发和续租读取
数据库实际返回的期限；被忽略的 INSERT/UPDATE 返回服务不可用，不生成虚假的交接秘密或
续租成功结果。正常五秒租约、最长五分钟交接及原有更早期限的裁剪规则保持原样。

过期会整体回滚本次 offer、续租、读取消费、staged 名称、成功审计和 `file.clean` 完成
标记，不增加 offered/read_started/staged 成功指标。失败的读取不返回 permit，失败签发
不返回下载秘密。Host 凭据、文件或 grant 到期沿用 `files.ErrAccess`；租约和交接到期
沿用 `files.ErrStale`，数据库查询/写入失败仍为 `files.ErrUnavailable`。

这些检查不撤回已经写入对象存储或原生附件库的字节，也不把曾经发生的读取改成未发生。
staged 仍是当前交接下的 Host 报告，与消息是否被原生 Agent 接收分别对账。过期后的
`EndHandoff` 清理继续可用；如果文件、授权和当前 Host 仍有效，可以申请新的 handoff ID
和一次性下载秘密。它不会延长旧秘密，也不自动重放原消息或恢复旧原生 receipt。

提交前检查是本次准入决策点；COMMIT 和响应可能随后完成，不承诺权限保持到客户端收到
应答。持续读取仍受原有 Host 生命周期、租约定时器及周期数据库检查约束。所有权限版本、
角色、会话/工作区范围、scanner policy、摘要和一次性密钥证明规则继续执行。

## 验证

隔离 PostgreSQL 回归先复现 22 个过期后仍成功的时序，覆盖五类独立期限下的签发、续租、
读取及 staged 写入，另覆盖读取状态触发器与 `file.clean` 完成标记等待。修复后逐项确认
真实锁等待，按数据库时钟等到过期后释放锁，核对整条 handoff 记录、审计、完成标记和
成功指标都保持原样。测试只缩短夹具记录期限，不改变系统时钟或生产 TTL。

另验证 INSERT/UPDATE 被忽略时不能返回成功，失败后正常写入可恢复；旧租约失败后仍可
退休并申请新交接，新秘密只能消费一次。原有并发消费、错误签名不消费、scanner policy /
epoch / connection / 设备 / grant 隔离和提交失败回滚测试继续运行。

完整 Go race/隔离 PostgreSQL 覆盖实际文件链路，正常本机 npm DSH `0.2.1-rc.2` 双节点
终端组合单独回归。身份、模型、对象存储及扫描对端为本地夹具；本轮不修改 Android APP，
不运行大负载、真机或厂商推送配置，也不声称学校生产与真实存储/病毒引擎已验收。
