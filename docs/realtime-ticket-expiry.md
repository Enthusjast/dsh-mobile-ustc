# Ticket 准入的实时期限检查

手机 ticket 签发、握手准备/消费和已建立连接的 grant 检查都按数据库当前时间判断授权期限。
事务内的行锁可以固定设备、组织、资源、授权版本和范围，但不会阻止时间流逝；事务开始时
有效的 grant，可能在等待 runtime 或审计锁期间已经到期。

签发使用 `clock_timestamp()` 筛选当前 grant，在资源检查完成后及审计写入后、准备提交前
再次复核期限。grant 已过期时不返回新 ticket，回滚本次 ticket 和成功审计。刚生成的 ticket
若在存储等待期间也已到期，同样不能作为有效凭据返回。

Prepare 保留 ticket 不消费的语义，但在当前授权/资源检查完成后重新检查 grant 和 ticket
的期限。Consume 在完成密钥证明后的事务内再次检查，并在消费及审计写入后、提交前复核。
过期会整体回滚，`consumed_at` 和本次成功审计都不保留；未消费的过期 ticket 仍不能使用，
原 grant 的更新/版本变化也不会使旧 ticket 恢复资格。

已建立 socket 使用独立的协商租约，原来的三十秒 ticket 只控制接入。运行中的
`ValidateRealtimeLease` 只重新检查当前 grant 到期；连接自身的期限仍由 Relay 原租约执行，
不会因为准入 ticket 已过期就把有效的五分钟 socket 提前关闭。设备、成员、安装、runtime、
grant 版本及范围检查继续适用，周期批量验证和每个业务操作的授权检查保持独立。

时间复核在已经锁定当前权限行的事务中查询数据库墙钟，避免 `now()` 固定在事务开始时间，
以及检查表达式在等待行锁之前已被求值的问题。提交前检查是本次准入的授权决策点；数据库
提交或网络应答可能在其后完成，不把应答到达时间当作权限生效时间。

签发因权限到期返回既有 `access.denied`；过期的 Prepare/Consume 返回既有无效 ticket。
数据库错误仍使用固定错误码，并保留原有的仅确认中止事务重试规则。到期属于业务拒绝，
不会因此重做十六次事务。token 仍只有摘要入库、保持单次消费，正常 ticket 的三十秒期限
与 WSS 协议/成功响应格式均未改变，也没有新增数据库迁移。

## 验证

修复前，真实隔离 PostgreSQL 回归复现八项过期后仍成功的时序：issue/prepare/consume/lease
等待权限行锁跨过 grant 到期、Prepare 等待期间 ticket 到期，以及 issue/consume 在审计
等待后跨过 grant/ticket 到期。修复后拒绝这些操作，并检查失败事务没有留下本次新 ticket、消费
状态或成功审计。另有正向用例确保已建立租约不被旧准入 ticket 的期限替代。

用例使用短期限的测试 grant/ticket 和真实行锁/审计触发器，等待依据 PostgreSQL 当前时钟，
不调整系统时钟或生产 TTL。这些边界夹具与正常本机 npm DSH 0.2.1-rc.2 联合链路分别验证；
身份和模型仍为本地夹具。新增数据库墙钟查询的目标负载成本尚未测量，本轮按约束跳过大负载、
Android APP、真机与厂商推送配置。
