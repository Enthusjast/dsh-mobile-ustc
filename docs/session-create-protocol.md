# Remote session creation

Both peers negotiate `command.relay.v1` and `session.create.v1`. The phone sends `session.create` with request/runtime UUIDs, the current `runtime_epoch` and payload `{workspace_id, preset}`. No session UUID exists yet. Relay rejects stale epochs, arbitrary paths, extra fields and caller-supplied identity/digests. Presets are ASCII tokens of 1–128 letters/digits/`.`/`_`/`-`, starting with a letter/digit; the host additionally requires an exact configured preset. The host resolves the workspace UUID to exactly one configured local workspace and reuses the same in-process DSH controller.

The body digest is SHA-256 of JCS over `{type, runtime_epoch, payload}`. The host journal uses that same epoch-bound body, persists acceptance before dispatch and records the result only after the native session checkpoint succeeds. Ambiguous creation is not replayed. A terminal rejection/unknown receipt does not tear down unrelated subscriptions. Creation progress uses `command.receipt` with `payload.workspace_id` and no `session_id`; settled host receipts include the result session UUID and metadata-only `payload.created_session`. Relay returns the workspace and result UUID to authorized sockets that negotiated creation; native IDs remain host/control-plane metadata.

Migration 005 allows a creation command to exist before a session UUID is known. It stores the authorized workspace UUID, request/user/device/runtime identity, canonical body digest and delivery state. Creation parameters, presets, local paths and bodies are not stored by the control plane. Existing message/cancel rows retain their session target and need no data rewrite.

Admission requires explicit `session.create` in the ticket and current grant, an authorized workspace in that runtime, current user/device/key/version, organization membership and active installation/runtime/grant. A session-only grant cannot create a new session. Creation and existing-session commands use the same `(device_id, request_id)` namespace; retries preserve the target and digest, including after the result session becomes known. Pending and unknown commands can be queried through the existing authorized command-status endpoint using their workspace target.

The current installation/runtime connection may report creation progress without a session UUID. A settled receipt must supply metadata for a persisted, available/running session in the command's workspace. The store validates the UUIDv5 native-to-mobile mapping, inserts or matches the session metadata, and atomically records the result UUID and settled command state with audit. A database error rolls all those writes back. No session body is accepted. Existing catalog synchronization may independently publish that same metadata; a delayed creation result preserves newer catalog state and cursor.

`npm run test:remote-dsh` creates the session through the actual Go Relay and installed npm DSH 0.2.1-rc.2. It checks durable creation receipts, one native session after matching retries, changed-preset conflicts, workspace denial, host preset rejection, REST status and directory visibility, then continues that same session through messages, reads and cancellation. Identity/model/key providers are local fixtures. The isolated PostgreSQL suite applies migrations 001–005 and covers workspace/action/key/grant denial, pending status, cross-operation request conflicts, unknown progress, invalid metadata, stale connections, atomic rollback after an injected command-update failure, duplicate settlement and retry after completion. Go socket tests cover scope/capability isolation and no forwarding on settled retry; host tests cover persisted result reconstruction and ambiguous-operation denial.

The [Android foreground creation flow](android-session-creation.md) now selects scoped host options, persists the original workspace intent and separate result UUID, reconciles unknown status and refreshes the directory before opening the result. Production identity/key provisioning, physical-device and load/failure acceptance remain open. A process restart changes the epoch: inspect the original command status and use a fresh request ID only for new creation intent. Never change the epoch on an ambiguous existing request to force it through.

Apply 005 after 004 before using the updated Go service. Rollback refuses to remove creation-command evidence when any workspace-targeted command exists. Reconcile and preserve that evidence explicitly before attempting a downgrade; the down migration never deletes it automatically.

The additive `session.create_options.v1` extension publishes bounded metadata on the current host connection using `session.create.options` / `.ack`. An authorized phone requests `.get` and receives `.result` for its literal workspace scope and current runtime epoch. The service retains at most 16 MiB of option bodies across live hosts; snapshots allow 128 workspaces and 128 preset tokens, with explicit public labels bounded to 32 scalar characters/128 bytes. Local paths, workspace references, preset definitions and model credentials are absent. Unknown or unsupported metadata leaves older Relay operations independent. The host rechecks the exact mapping and configured preset on creation.
