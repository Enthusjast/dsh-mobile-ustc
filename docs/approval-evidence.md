# 审批签名证据的事务内保留

迁移 `025_approval_decision_evidence` 在新审批决定成功写入时，同一事务保存签名 JWS、当时
已登记并经应用验签的设备审批公钥，以及审批、设备、代次、决定和绑定摘要等必要元数据。
审批审计或证据写入失败会回滚决定；无效签名不会产生证据。设备之后撤销或更换密钥时，已保存的
公钥快照不随之改变。快照只保存验签所需的曲线和坐标，不复制设备公钥的可选标签。决定的签名
绑定字段不可修改，主机结果和审批终态仍按原状态机更新。
迁移 027 同时固定原始 JWS 字节的 SHA-256，防止另一份对相同内容有效的签名替换原始证据。

证据只用于历史核查，不恢复旧授权、回调或执行能力。签名 payload 包含决定、标识、nonce 和
上下文摘要；证据不保存工具参数、工作区原始路径或完整审批上下文。公钥和签名可以验证签名及
已保存的绑定摘要，但单凭这份证据不能重新生成被摘要的工具参数，也不能证明学校身份系统、
认证强度或当时的授权策略配置。运维需另外保全适用的身份和策略证据。

迁移前已作出的决定没有可信的“当时公钥”快照，迁移不会用当前设备密钥伪造历史记录。
旧决定原有的签名和审计仍保留，但不能当作本迁移捕获的独立证据；需通过已有备份和可信来源
另行评估。重新发送旧决定也不会补造快照。

## 部署与访问

升级时先停止或隔离审批写入，应用迁移并配置数据库权限，再启动包含该迁移适配的所有节点。
审批写入角色除原有权限外，需要对 `approval_decision_evidence` 的 SELECT、INSERT 权限及对
`approval_decision_evidence_material` 的 INSERT 权限；它不需要读取证据材料。缺少权限或
证据写入失败会使审批决定失败并回滚。审批决定还需要读取恢复状态并持有行锁；可将恢复状态表
的 UPDATE 权限限于受约束的 `slot` 列，无需授予修改代次或阶段的权限。迁移 027 后还需对
`approval_evidence_fingerprints` 的 INSERT 权限。迁移不会为部署自动创建角色或向 PUBLIC 授权。

历史核查角色需要单独授予受控 SELECT 权限；数据库访问审计由部署方配置。证据包含设备和用户
标识、签名及公钥，应按敏感元数据保护。迁移 025 在已有证据身份时拒绝 down；需要变更时
使用审阅后的前向迁移。安装 025 后，旧的 006/007 迁移也不能越序删除证据所依赖的审批字段；
已有签名摘要时迁移 027 同样拒绝 down。

## 验证历史证据

迁移 027 会在锁定证据写入的同时检查已有快照：只有签名、审批记录和保留的绑定一致，才为
旧快照补记摘要；原记录缺失或不一致时不补造摘要。补记不是独立外部见证，不能证明迁移前
数据库从未被特权角色篡改。新决定的摘要则与决定、签名和公钥在同一事务中写入。
摘要和材料仍保存在同一数据库；超级用户可绕过普通保护并同时改变两者，需要外部受控备份和
独立访问审计，不能把本地验签当作独立防篡改见证。

使用单独的受控数据库角色和当前外部代次，执行：

```sh
export REMOTE_DATABASE_EPOCH='<当前部署代次 UUID>'
.local/remote archive verify-approval \
  --approval-id '<审批 UUID>' --expected-epoch "$REMOTE_DATABASE_EPOCH"
```

工具检查原始签名摘要、JWS 格式和签名、公钥指纹及保留的决定绑定；结果只含审批 ID、来源与
当前代次、决定和验证时间，不返回签名、公钥、用户或设备 ID。`fingerprint_source` 为
`captured` 或 `backfilled`，表明摘要取得方式。成功、无效、材料不可用和来源谱系不匹配的
尝试都会写 `approval.evidence.verify` 审计；审计不可用时不会返回成功。数据库级拒绝访问和
其他直接 SQL 读取仍需部署方的数据库访问审计。验证时间是审计行的数据库插入时间，只有事务
提交后才返回成功；输出丢失后重试会产生新的读取审计。

验证只证明签名和保留记录之间的关系，不会重新检查当时的完整工具参数、认证强度或当前授权，
也不授权再次执行。恢复后的新代次只有在已释放谱系连接到来源代次时才能验证旧证据；隔离时
拒绝验证。缺少材料或摘要的记录显示为不可用，不会自动重造。

验证角色需 SELECT 证据、材料、摘要与恢复记录；对材料的行锁可将 UPDATE 限于 `approval_id`
列，触发器仍拒绝修改；恢复状态表锁可将 UPDATE 限于 `slot` 列。角色还需向 `audit_log`
写入审计、读取返回的 `ts` 列及使用其序列。具体验证和删除权限应与普通审批写入角色分开。

## 保留和恢复边界

新捕获的证据材料从数据库决定时间起至少保留一个 UTC 日历年。到期后，具备单独 DELETE 权限
的管理角色可显式删除材料；只有数据库处于 ready 且 `approval.evidence.material.delete` 审计
同事务提交时才允许删除。证据身份永久保留，避免到期删除后借重试重造历史。这里没有自动删除
调度、追加法律保全或按组织配置更长年限的接口；有更长要求时应通过权限及外部保全流程禁止
提前删除。

删除的是独立快照表中的材料，不会删除 `approvals` 中现有的决定 JWS 或设备表中的公钥；
不能将它理解为这些数据的完整擦除。数据库备份恢复后证据仍属于来源数据库代次，恢复隔离
会使旧授权失效，不会借证据重放决定。

这一步尚未实现审批证明或完整审计日志的外部冷归档、自动冷热分层、密钥保管与生产备份。
[控制事件加密导出](control-cold-export.md)不包含这些审批证据。需要独立部署加密备份、
访问审计和恢复演练，不能据此宣称计划中的完整审计保留要求已完成。

## 本地验证

隔离 PostgreSQL/race 用例验证签名快照、设备密钥轮换后仍可校验、重复决定、证据与审计故障
回滚、受限写入角色、到期删除审计、旧决定不虚构快照，以及真实 `pg_dump` / `pg_restore`
后证据保留且旧授权不复活。验签用例还覆盖错误公钥、记录变化、另一份有效签名、补记边界和
审计失败。模型、身份和密钥均使用本地夹具。
