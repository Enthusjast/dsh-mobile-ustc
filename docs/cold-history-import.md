# 审计和审批证明的历史导入

迁移 `030_cold_history_imports` 可以将已经认证的[审计加密批次](audit-cold-export.md)或
[审批证明文件](approval-evidence-export.md)导入独立的 PostgreSQL 历史表。它保留原始来源和
保留期限，只写入历史文档及一条管理审计；不会把原审计行写回热表，也不会创建审批、恢复记录、
设备或授权，更不会重放事件或签名决定。

导入前必须独立确认文件来源、归档域、密钥和适用策略。持有归档对称密钥的人能够生成通过
加密认证的文件；审批文件还会验证保存的 JWS 字节摘要、公钥和签名，但这本身不能证明公钥
与学校身份的历史关联或恢复实时授权。文件内的来源谱系会校验到导出代次；目标数据库只接收
惰性历史，不要求将外部来源声明为目标数据库的祖先。恢复库必须先完成[隔离和释放](database-recovery.md)。

## 权限与操作

迁移不创建数据库角色或向 PUBLIC 授权。导入角色需要对 `cold_history_imports` 和
`cold_history_import_payloads` 的受控 SELECT、INSERT，以及对后者 `import_id` 列的 UPDATE
权限以持有重试时的行锁；触发器仍拒绝实际修改。角色还需要读取恢复状态并锁定受约束的 `slot`
列、向 `audit_log` 写入管理审计及使用序列。普通服务角色不需要读取历史正文。直接 SQL 读取
历史和文件访问应由部署方的数据库/系统审计记录。

在备份之外保存稳定的归档域、当前部署代次和唯一导入 UUID。密钥文件和目录要求与
[控制事件导出](control-cold-export.md)相同；数据库连接从受控环境注入。以下命令在仓库根目录执行：

```sh
export REMOTE_ARCHIVE_DOMAIN_ID='<外部保存的归档域 UUID>'
export REMOTE_DATABASE_EPOCH='<外部保存的当前数据库代次 UUID>'
.local/remote archive import-audit \
  --import-id '<本次导入 UUID>' --export-id '<来源导出 UUID>' \
  --expected-epoch "$REMOTE_DATABASE_EPOCH" --domain-id "$REMOTE_ARCHIVE_DOMAIN_ID" \
  --key-id '<密钥标识>' --key-file /受控目录/archive.key \
  --directory /受控目录/audit-archives
```

导入审批证明时使用 `archive import-approval` 和审批证明文件所在目录，参数含义相同。两种
文件类型不能互换。程序先验证文件，再将完整历史文档、操作身份和 `cold.history.import` 审计
在同一事务中提交；失败不会留下部分历史。结果只包含类型、操作/来源/目标标识、数量、文件
摘要、大小和时间，不输出源审计内容、JWS、公钥、用户/设备 ID、路径、密钥或数据库连接。

输出丢失时使用相同导入 UUID、文件、域、密钥和目标代次重试；受保护的副本目录可以不同。
重试会比较保存的完整文档并记录 `cold.history.import.verified`。同一类型、域和导出 UUID
只能归属于一个导入操作；不同导出文件仍可能包含同一条历史事实，人工核查应按来源 ID 去重。
已到期或冲突的数据库重试也记录失败审计；审计不可用时操作失败。数据库再次恢复并换代后，
旧导入操作不能绑定新代次。

## 历史读取与保留

文档保存在 `cold_history_import_payloads`，由独立历史读取角色按导入 UUID 查询；内容以明文
保存在受数据库 ACL 和静态加密保护的数据库中。审计文件的每条原始 JSON 字节以 `source_base64`
保存，原来未知的逐条来源代次仍为未知；导入摘要里的 `source_epoch` 对审计文件表示批次代次，
不是对每条旧记录来源的推断。审批文档包含签名与公钥，不含完整工具参数。

历史沿用文件内的 `retain_until`，不会从导入时间重新起算；来源已过期时，可由独立受控角色
显式删除历史正文。删除只在数据库 ready 且 `cold.history.import.delete` 审计同事务提交时
成功；操作身份永久保留，防止同一文件借重试或新 UUID 被重新导入。没有自动删除调度或追加
法律保全接口，更长保留要求需由组织设施和权限策略处理。存在导入身份时迁移 030 拒绝 down。

审计文件明文上限 64 MiB、审批文件上限 8 MiB，处理时可能使用数倍文件大小的内存。最大
尺寸和目标负载尚未验证；文件损坏、密钥不符、来源不完整或超出边界时失败，不能跳过数据。
数据库静态加密、外部备份、密钥保管、生产访问审计和恢复目标仍需独立部署与验收。

## 本地验证

小型隔离 PostgreSQL/race 夹具覆盖两种文件认证、跨类型拒绝、幂等与并发、审计失败回滚、
存储损坏、到期删除、防止重导入以及真实 `pg_dump` / `pg_restore` 后不复活旧授权。实际服务
二进制验证输出丢失后的同 UUID 对账和无敏感内容输出。未运行最大文件、大负载或真机测试。
