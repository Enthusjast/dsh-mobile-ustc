# Approval signature foundation

The host and Go service share an approval context/decision contract, RFC 8785 canonical bytes and independent ES256 JWS verifiers. The [host journal](approval-journal.md) adds durable one-use decisions and synchronous consumption, verified through a native DSH guard test adapter. [Approval control](approval-control.md) adds transactional metadata registration and current-owner/assurance decision acceptance. The [configured server transport](approval-protocol.md) now supports HTTPS/WSS approval routing; the [normal host owner](approval-native.md) now connects verified authority to native guard/body consumption. A verified signature alone grants no execution authority, user-verification assurance or replay protection.

`contracts/security/approval.schema.json` is generated from the TypeScript schemas; `npm run contracts:check` checks it alongside the M0 contract. The validators enforce additional byte, Unicode, nonce, date/lifetime and resource-uniqueness rules documented in its description. `jcs-vectors.json` supplies shared canonical bytes/digests for nested data, UTF-16 property order, ECMAScript numeric boundaries, Unicode escapes, prototype-like names and rejection cases. `approval-signatures.json` contains public test keys and Node/Go-produced signatures, with independent valid allow/reject samples and invalid mutations. It contains no signing private key. Kotlin still needs to run the same vectors when the Android implementation is added.

Canonicalization uses pinned implementations from the RFC's implementation ecosystem: Node `canonicalize` 5.1.0 and the Go reference implementation at `github.com/cyberphone/json-canonicalization`, commit `32a48195b9b2`. Wrappers reject duplicate JSON members at every level, invalid UTF-8 or lone UTF-16 surrogates, non-finite numbers, non-object roots, more than 32 levels/16,384 values and more than 128 KiB. The Node value API additionally rejects accessors, toJSON methods, sparse arrays, cycles, non-plain objects and unsupported JS values before serialization. Numeric arguments use finite IEEE 754 semantics; larger exact numeric values must use strings. Existing command digests retain their prior formats.

The context binds the domain/protocol, host/installation/runtime/epoch, mobile and opaque native session identities, approval/execution/native call IDs, actual tool/arguments, workspace root digest, explicit resource version facts, a 32-byte random nonce, policy version, required assurance profile/age and request times. Resource facts are unique by kind/identity. Empty resource facts explicitly assert no additional file/repository snapshot; they do not implicitly freeze a working tree. The module validates and hashes the supplied facts. It does not resolve resource ownership or calculate/check those facts against live files. The pending-request producer and final execution guard must do that.

Decision payloads bind the same routing/execution identity, context SHA-256, allow_once/reject, user/device/key version, policy, nonce and times. Compact JWS is ES256 only, with protected header exactly `{alg, kid, typ}`. Type is `dsh-approval-decision+jws`; key ID is `dsh-approval/<device UUID>/<key version>`. Header and payload must both already be JCS UTF-8, all base64url components must be canonical/unpadded, and signatures must be 64-byte JOSE encoding. The verifiers use Node `jose` 6.2.13 and Go `go-jose/v4` 4.1.6 with a trusted registered P-256 public key; private material, caller key headers, key URLs and unrelated header/claim fields are refused. Public coordinates and registered thumbprints must match their canonical encodings.

Times are UTC strings with exactly millisecond precision, compared using a millisecond clock. Request lifetime is positive and at most 180 seconds. Verification allows at most five seconds of future clock skew, requires an unexpired request and decision, accepts a decision issued at most 30 seconds earlier, and never allows its expiry to exceed the request deadline or precede its issue time. Expiry itself has no positive grace period. These version-one limits must be reflected in the eventual phone signer and deployment clock policy.

Verification returns the decision claims, canonical payload and its SHA-256 for subsequent state handling. It is deliberately pure: repeated verification can succeed, and both equivalent ES256 signature encodings can represent the same canonical decision. Future one-use/CAS logic must use pending identity/nonce and canonical decision semantics, never treat a different signature byte string as a fresh approval. Failed verification mutates no nonce or pending record and returns a generic error without context/payload bodies.

Go/TypeScript tests cover canonical bytes/digests, Node/Go signing directions, equivalent signatures, changed context facts, altered decisions and identities, wrong purpose/key/version/policy/nonce, expiry/future issue time, unknown/case-aliased fields, malformed Unicode, duplicate members, noncanonical JWS/coordinates and DER signatures. Go explicitly requires exact JSON field names instead of relying only on encoding/json's case-insensitive struct matching. Tests also confirm that the pure verifier does not masquerade as a pending-state consumer. Run `go test -race -count=1 ./...` from `services/remote` when changing shared vectors: those files live outside the Go module, so a cached test result is insufficient. Existing DSH/control-plane integration remains separate compatibility evidence.

The [signed lease provider and independent verifier/cache](approval-leases.md) now bind current owner/key/grant/assurance to the exact decision and host connection. Before signed approval may enable production execution, remaining work includes exposing these controllers through authenticated transport, authority key provisioning, production account/key provisioning and revocation hooks, remaining capability/platform coverage, and Android signing/user verification. Normal callback/body/guard ownership and signed request/details/result transport now have local CLI/service evidence. Invalid signatures must be rejected before any nonce is consumed, conflicting decisions must not overwrite a terminal one, and restored history must never recreate an executable callback. The legacy local M0 answerer remains separate from the provisioned signed owner.

Primary references: [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785), [reference implementations](https://github.com/cyberphone/json-canonicalization), [Node canonicalize](https://github.com/erdtman/canonicalize), [Node jose](https://github.com/panva/jose), and [Go JOSE](https://github.com/go-jose/go-jose).
