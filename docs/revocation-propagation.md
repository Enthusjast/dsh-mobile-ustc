# Active connection revocation

The production Go entrypoint runs two independent workers for a single Relay process. A 250 ms poll consumes committed `device.revoked`, `runtime_grant.updated` and `runtime_grant.revoked` outbox events. It marks affected sockets as closing, sends a metadata-only `access.revoked` frame and closes the transport even if notification fails. Only then does it acknowledge the event with `published_at`. A crash before acknowledgement replays the idempotent invalidation. Approval pending/decision/end/result topics now enqueue bounded metadata references for the [optional approval transport](approval-protocol.md), and authorization-prepared topics are acknowledged without claiming execution. Other topics remain pending for their consumers.

Device events target every authenticated socket for that device. Grant events target the matching runtime/user only when the socket's grant version is older than the event version. Delayed enrollment events, retries and older grant updates therefore leave connections with a current grant intact. Closing sockets cannot admit new subscriptions or serve as host command routes. Disconnect releases subscriptions and asks the host to abort its native followers.

An independent one-second worker checks all authenticated, non-closing connections against PostgreSQL in batches of at most 128. Device checks cover active user, device key/version, organization membership, host/installation/runtime, exact grant version, expiry and scope/resource ownership. Host checks cover the installation key version and current runtime epoch/connection; credential expiry also applies. Foreground commands, receipts and content still perform their existing authorization checks.

Each worker operation has a two-second deadline. Failed or timed-out authoritative checks close all connections sampled for that check, including those from earlier batches. Notifications get a separate 250 ms deadline and use `access.revoked` with code `internal` when authority is unavailable. Event backlog does not delay lease checks. Logs report availability transitions without payloads or raw database errors.

`npm run test:remote-dsh` exercises the production entrypoint, isolated PostgreSQL and installed npm DSH 0.2.1-rc.2. It revokes an idle sibling device, verifies the primary phone can still page history, then revokes the primary user's grant while idle. Both sockets must receive `access.revoked` and close within five seconds; supported outbox events must be acknowledged afterward. The 2026-10-24 run closed the grant socket in 269 ms, including the HTTP call and polling. This local fixture result does not establish latency under target load.

Go tests cover duplicate delivery, apply-before-acknowledgement, failed-apply/failed-ack retries, independent workers, grant-version targeting, batched validation, invalid peers and authority failures. The isolated PostgreSQL suite checks the actual batch query, expiry, key/epoch/connection mismatches and outbox acknowledgement. Database outage behavior currently has component-test evidence; sustained target-load and real database-failure window measurements remain open.

This outbox acknowledgement design currently supports one Go Relay process. Durable fanout and per-node delivery tracking are required before multi-node deployment. Periodic authoritative checks do not replace that work. Mobile lease renewal and production identity/key-provider integration also remain open.
