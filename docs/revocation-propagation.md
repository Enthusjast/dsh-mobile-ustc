# Active connection revocation

The production Go entrypoint runs [independent per-node control consumers](control-fanout.md). A 250 ms poll reads committed `device.revoked`, `runtime_grant.updated` and `runtime_grant.revoked` outbox events for this node. It marks affected mobile sockets as closing, sends a metadata-only `access.revoked` frame and closes the transport even if notification fails. Only then does it persist this node's acknowledgement. A crash before acknowledgement replays the idempotent invalidation; another node's acknowledgement cannot consume the delivery. Approval pending/decision/end/result topics enqueue bounded metadata references for the [optional approval transport](approval-protocol.md), and authorization-prepared topics are acknowledged without claiming execution. Other topics remain for their consumers. The legacy `published_at` means a local publication occurred, not that all nodes finished.

Device events target every authenticated socket for that device. Grant events target the matching runtime/user only when the socket's grant version is older than the event version. Delayed enrollment events, retries and older grant updates therefore leave connections with a current grant intact. Closing sockets cannot admit new subscriptions or serve as host command routes. Disconnect releases subscriptions and asks the host to abort its native followers.

The device-revocation transaction also inserts one `approval.device.revoked` per distinct runtime with that device's accepted, unspent, unexpired allow decision. An insertion failure rolls the entire revoke back. This avoids disclosing arbitrary device IDs to unrelated hosts or organizations. These scoped device events and existing runtime/user grant events send `approval.invalidate` to the current signed host, bound to its exact runtime/epoch/connection. Hosts retain device tombstones and monotonic grant-version floors, recheck them after asynchronous verification, and cancel affected work before actual body entry. Equal/newer grant versions, unrelated actors and already-started tools are unaffected. A 250 ms notification deadline or a legacy signed host without `approval.invalidation.v1` closes the host connection/cache. Short signed leases still bound authority when events are delayed. These negative authority events acknowledge notification or connection closure, not native execution.

An independent one-second worker checks all authenticated, non-closing connections against PostgreSQL in batches of at most 128. Device checks cover active user, device key/version, organization membership, host/installation/runtime, exact grant version, expiry and scope/resource ownership. Host checks cover the installation key version and current runtime epoch/connection; credential expiry also applies. Foreground commands, receipts and content still perform their existing authorization checks.

Each worker operation has a two-second deadline. Failed or timed-out authoritative checks close all connections sampled for that check, including those from earlier batches. Notifications get a separate 250 ms deadline and use `access.revoked` with code `internal` when authority is unavailable. Event backlog does not delay lease checks. Logs report availability transitions without payloads or raw database errors.

The optional [private operational metrics](operational-metrics.md) now observe each worker's availability, last success and duration. Outbox metadata retains the database creation timestamp; only successful local apply/publication acknowledgement contributes an age sample. Apply/ack failures and future database timestamps are counted separately. Connection invalidation counts are deduplicated per connection even when outbox events repeat. These measurements describe local processing, not remote execution or multi-node fanout.

`npm run test:remote-dsh` exercises the production entrypoint, isolated PostgreSQL and installed npm DSH 0.2.1-rc.2. It revokes an idle sibling device and verifies the primary phone can still page history. It then holds an approved native Bash invocation after guard and revokes the primary user's grant. The body must remain unexecuted and the host must report durable invalidation before its three-second lease expires. Both revoked mobile sockets receive `access.revoked` and close within five seconds; supported outbox events must be acknowledged afterward. The 2026-10-24 run closed the grant socket in about 265 ms, including the HTTP call and polling. The content check follows the ordered `access.revoked` marker: already-queued authorized frames can arrive during the HTTP request. This local fixture result does not establish latency under target load.

Go tests cover duplicate delivery, apply-before-acknowledgement, failed-apply/failed-ack retries, independent workers, grant-version targeting, batched validation, invalid peers and authority failures. The isolated PostgreSQL suite checks the actual batch query, expiry, key/epoch/connection mismatches and outbox acknowledgement. A bounded [database connection outage drill](database-outage-drill.md) now exercises both production relays with an actual npm DSH Host: old connections close, relays exit on lost authority, and explicit restart after natural ownership expiry preserves native command facts without replay. Sustained outages and target-load failure windows remain open.

Durable per-node delivery tracking, snapshot checkpoints and stable-node restart replay now have PostgreSQL and two-process evidence in [control fanout](control-fanout.md). This closes the single-consumer acknowledgement limitation. Cross-node content routing, cluster target-load/failure windows, mobile lease renewal and production identity/key-provider integration remain open; periodic authoritative checks do not replace those gates.
