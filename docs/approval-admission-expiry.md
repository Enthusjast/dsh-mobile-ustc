# 审批登记与决定的提交前期限检查

审批登记和决定接收都在锁定当前资源后、事务提交前按 PostgreSQL 当前时间重新验证。
行锁可以固定连接归属、身份、密钥和授权范围，但期限会继续流逝；SQL 在等待行锁或触发器
前求值的条件，以及决定状态更新前的检查，都不能替代后续证据、审计和 outbox 写入后的检查。

登记检查原请求期限和 Host 的 45 秒心跳窗口。新登记和同参数登记重试都执行这些检查，
等待期间过期不能返回新的 pending 登记成功结果。

决定接收检查当前 Host 心跳、原请求与签名决定期限、决定签发的 30 秒新鲜度、当前 token、
认证时效和 grant 期限。最后的检查复用同一个 assurance 和签名决定验证器，保持原签名、
上下文、未来时间容差和边界规则；不会为了重试延长或重签决定。允许与拒绝决定使用相同
规则，同一决定的幂等重试也必须仍有当前权限。

过期或心跳失效会整体回滚本次事务：不保留新登记、决定消费、签名证据、证据材料/指纹、
成功审计或 outbox 事件，也不增加已提交状态转换指标。原有 pending 或历史决定保持原样，
它们不因为本次失败获得新权限。后续按原有到期、断线、状态查询和对账流程处理，不自动
批准、重放工具或将已知执行结果改成未执行。

失败沿用原有错误分类：登记请求到期为 `approval.expired`，Host 心跳失效为连接失效，
token/认证时效失败为 `approval.assurance_required`，grant 到期为 `access.denied`，
签名决定的期限/新鲜度失败为 `approval.decision_invalid`。数据库故障仍失败关闭。原有
1.5 秒数据库准入期限、正常 TTL、协议和数据库结构保持原样。

提交前检查是本次准入的决策点；COMMIT 和网络应答可能稍后完成，不声称权限一直有效至
客户端收到响应。服务端接收决定仍不代表工具已执行，Host 必须继续独立验证短期签名租约、
当前上下文、单次消费和最终 guard。

## 验证

隔离 PostgreSQL 夹具在修复前复现 21 个过期后仍成功的时序：登记等待审计/outbox 跨过
请求或心跳期限，允许/拒绝决定等待审计/outbox 跨过各独立期限，以及决定状态更新、证据
或材料触发器等待跨过 token 期限。修复后拒绝全部情况，并核对 pending、审计/outbox 与
不可变证据三张表的回滚。另覆盖登记重试等待原审批行、登记与已决定重试等待 runtime 行
时跨过期限，以及有效授权在真实写入等待后成功并幂等重试。

测试通过活动视图确认真实锁等待，再按数据库墙钟等待期限，不调整系统时钟或生产 TTL。
完整 Go race 与本机 npm DSH `0.2.1-rc.2` 双节点终端组合分别验证。身份、模型和签名信任
配置均为本地夹具；本轮不修改 Android APP，不涉及学校生产、大负载、真机或厂商配置。
