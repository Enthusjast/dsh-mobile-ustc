# Remote session cancellation

Both host and phone negotiate `command.relay.v1` and `session.cancel.v1`. The phone sends `session.cancel` with its request UUID, runtime UUID, the current `runtime_epoch`, authorized session UUID and an empty `payload`. Caller-supplied user/device IDs, digests and subscription fields are rejected. No session subscription is required, but the current grant and ticket must explicitly include `session.cancel` and cover that session or its workspace. `message.submit` alone does not grant cancellation.

Relay verifies the current host connection and rejects a stale epoch with `runtime.changed` before recording or forwarding a command. The authenticated user/device identity is attached by Relay. The body digest is SHA-256 of JCS over `{type, runtime_epoch, session_id, payload}`. Including the epoch prevents a delayed cancellation from being reused after the host process restarts. Message digests retain their existing format. The shared JSON Schema and device/forwarded golden frames are under `contracts/ws/v1`.

The host validates the command, identity, digest and epoch, then uses the current-process DSH session controller. It writes the command to the encrypted local journal, reports `host_accepted`, then `dispatching`, calls native `cancel`, persists the result and reports `settled`. The Relay persists metadata, digest and state only. A matching request UUID returns the stored status; it does not cancel another turn. A different operation, session or epoch with that UUID conflicts. Completed host journal entries may reconstruct `host_accepted` → `settled` when earlier Relay receipts were lost. An interrupted ambiguous mutation becomes `outcome_unknown`; it is not automatically executed again.

`settled` means the cancellation command returned its native acknowledgement. Clients follow the subsequent `turn/end` event to confirm that the active turn stopped. DSH 0.2.1-rc.2 retains pending inbox work when canceling. Already streamed text may be persisted as an `assistant/message` with `interrupted: true`; the turn ends with reason `aborted`. Cancel does not archive a session or release its Agent. `session.unsubscribe` continues to release only a follower.

`npm run test:remote-dsh` runs the actual Go entrypoint, isolated PostgreSQL and installed npm DSH. A local model fixture emits partial text, then waits for up to 30 seconds. The phone cancels through Relay; the test requires an aborted turn within five seconds, interrupted partial text, all durable command receipts, a `settled` REST status, no duplicate command, and rejection of a stale epoch before admission. A subsequent history request verifies that the subscription survives cancellation. Database dumps exclude the unique cancellation prompt and partial model text.

Go socket tests cover missing host/device capabilities, missing action, resource denial, stale epochs, strict empty payloads and no host forwarding on settled retry. PostgreSQL tests cover action authorization, type conflict and durable recovered settlement. Host tests verify retries call native cancel once and cannot move into a new epoch. These are local fixture results; Android UI, real model/tool cancellation, production identity/key storage and load/failure acceptance remain open. Existing local M0 cancel journal entries used the older digest; their request IDs conflict with the new epoch-bound digest and must not be reused for fresh cancellation intent.
